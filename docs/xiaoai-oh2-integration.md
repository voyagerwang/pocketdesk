# OH2 音箱接入工作台

2026-10-21。OH2是所选工作台小精灵的可选语音入口，复用已有助手会话、记忆、任务和成果记录。代码入口见[scripts/xiaoai](../scripts/xiaoai/CLAUDE.md)。

## 使用

先喊“小爱同学”，然后说“小精灵，……”或“波波，……”。首版每次指令仍需唤醒并带前缀，不承诺免唤醒连续对话或原始音频接管。

工作台回答会以“小精灵回复”开头，便于区分小爱的原生回答。目前真机曾观察到约59秒总等待。已取消6秒时的中途播报，业务结果返回后直接播最终回复，避免额外权限/睡眠/云端播报挡住结果；仍保留每次权限检查。SQLite timings只记分段耗时，不能将接口接受耗时当成实际出声耗时。2026-10-22已部署优化；一次查询现有待办的处理链路测得20.2秒（预检2.9秒、助手13.2秒、播报请求4.1秒），不含唤醒/识别，不与上一轮59秒创建请求视为同条件对照；实际出声需现场确认。原生回答可能先出现，不能把它误认为工作台的执行结果。

默认使用小爱设备自身音色，每次播报单独建立无Cookie存储会话，与后台识别轮询隔离。`voice system`可显式选择Mac Tingting备用音色：本机生成临时MP3，OH2通过随机URL获取；只在实际GET后记audio_requested，不把播放接口返回接受当成出声。该模式需要Mac和音箱局域网互通，临时音频三分钟有效，不提供目录或用户文件访问。`voice native`恢复用户选择的小爱默认音色；修改后install生效。默认不自动换音色。

- “小精灵，帮我创建一条明天整理资料的清单。”：默认交给另一台电脑。
- “小精灵，刚才那件事做到哪了？”：在同一目标的持久会话里追问。
- “小精灵，本机，帮我记一下……”：仅本轮选择本机；默认目标不变。
- “小精灵，在另一台电脑，……”：显式选择远程工作台。
- “小精灵，换个话题”：仅重置当前目标的会话绑定，旧会话保留。

默认远程入口是 `http://127.0.0.1:8786`。现场已确认监听进程是UU Remote，页面为示例工作台，助手工作目录为另一台电脑的 `/Users/<user>/Documents/workbench/data/sprite-workspace`。本机可选入口为 `http://127.0.0.1:8787`。8786是本机回环上的远程转发端口，不是另一台电脑的局域网IP；依赖UU连接保持在线。默认入口失败不自动回退本机，不改变用户实际操作的数据归属。

## 责任与恢复

云端识别由小米完成；只提取被绑定OH2的本次启动后、60秒内且具有明确前缀的记录。普通小爱指令不转发，不读取音频文件，不把音箱里积存的历史语音当授权。每次启动从当前时刻建立新门禁，停机期间的指令不会补执行。

通道在用户私有SQLite保存音箱指令、目标和回执，设备识别ID摘要作幂等键。发送前持久占用；工作台没有该通道的幂等提交协议，因此发送后超时/崩溃只记结果未知，不自动重发。排队/发送中请求在重启后保留待核对。播报失败不重跑业务，工作台已完成的结果仍可在对话中查看。启动前检查失败明确记为未发送。

音箱与工作台不共享凭据。米家 `auth.json` 只读，复用已有 passToken换取音箱专用服务会话；独立凭据0600，换账号后停止并要求重绑。只绑定一台明确OH2，并校验deviceID、miotDID及型号。这个绑定是独立的音箱入口授权，不扩大原单家庭MijiaGateway权限。只允许固定OH2文字播报动作5-3，以及明确回复请求前直读5.3睡眠属性；开启或未知即拒绝播报，不自动退出；睡眠写入只允许恢复开启；模型不能指定设备、动作或服务URL。睡眠退出未知不补写，也不继续假设能出声。媒体pause不是取消原生助手的可靠协议，已移除自动暂停；首版可能先听到小爱原生回答，再听到工作台结果。

现场恢复：OH2固件1.54.82在睡眠开启时，MIOT和MiNA播报都返回接受但实际无声；退出睡眠后，用户确认听到测试回复。此前自动核验并退出睡眠的实现已在2026-10-22事故排查中撤回；现在开启或未知即拒绝播报，设备请求边界也禁止解除睡眠。现场2.2静音属性读回仍为true但已经实际出声，不能仅凭这个字段认定TTS一定静音。审计原始工具记录确认：2026-10-21 23:17曾同时尝试将2.2静音与5.3睡眠写为false；静音随后读回仍true，睡眠读回变为false。未发现音量、勿扰或原生家居授权写入接口调用，但这不足以排除间接影响。初始睡眠值已保存在私有audio-state-before.json，需要恢复时先stop，再运行restore-sleep。

工作台请求固定到两个已配置的回环入口，不跟随重定向、不读取系统代理、不传小米凭据。如果工作台启用访问令牌，首版会明确失败；不能禁用其鉴权来接入。该通道不实现新模型或第二套任务执行器。播报只使用工作台返回的回复，截短Markdown与长内容；已接收/已启动不能替代成果核验。长任务最终成果以工作台实际任务记录为准，首版不保证后台任务完成后主动播报。

## 唤醒音乐闹钟

2026-11-02。到点不是念一句“该起了”，而是放一段用户显式安装的轻音乐——念话会被当成在跟你说话，音乐不会。

安装：`manage.py alarm --file /path/xxx.mp3`（只收 MP3、8MiB 以内），文件复制到私有目录 `xiaoai/audio/alarm/`，`config.json` 只记文件名；`manage.py alarm --test` 立刻放一次供现场确认，`--off` 撤销。播放复用备用音色的那条通道：本地起随机单文件 URL，音箱自己来取，**音箱实际 GET 才记 `audio_requested`**，云端返回接受不算出声。

到点行为：只放音乐、不念话。闹钟是用户亲自排定的出声时刻，**睡眠开关不拦闹钟**——实测：睡眠为开时音箱照样取流播放；普通播报仍严格拒绝睡眠状态，这里不解除也不改写睡眠，只在台账里记下当时是 `sleep_on` / `sleep_off` / `sleep_unknown`。没有安装音乐记 `no_music`；迟到超过 10 分钟记 `missed`（九点响八点的铃没有意义）。已经播过的不再重复触发。

说话登记：`wake_alarm` 工具（`Sources/WakeAlarmRequest.swift`）把“几分钟后叫我”“明早八点用音乐叫我”换算成绝对时刻，走下面这个回环端口登记，回执就是那句“已定好：08:00 用音箱音乐叫你”。睡眠状态读取改走米家只读属性端点（`scripts/xiaoai/scope.py --sleep`，范围仍只有冻结 OH2 的 5.3），因为 MiService 的会话式 MIOT 对本账号长期返回 `-127 client withdraw`。

喊停：闹钟响起后说“关闭播放 / 停止播放 / 别响了 / 安静点”会调用音箱的 `player_play_operation stop`（`scope.py` 只放开“停下”这一个播放器动作，不许调音量、换内容）。只在闹钟真的响过之后的 3 分钟内允许喊停，避免误掐用户自己在放的音乐；还没响的那条会被直接取消。也可以说“小爱同学，停止播放”让音箱自己停。

登记入口：`bridge.py` 起一个只绑 `127.0.0.1` 的控制端口，端口与本次进程的随机 token 写在 `xiaoai/control.json`（0600，停服务即删）。`POST /alarm {id, due}` 只接受 8–64 位 id 和未来 30 天内的绝对时刻，重复 id 返回 409、不覆盖已有时刻；`GET /alarm` 查、`POST /alarm/cancel` 取消。这个端口只登记时间，不承载设备动作、文本或任意路径，访问必须带 `Authorization: Bearer <token>`，非回环来源直接拒绝。音箱能访问的音频端口不承载这些路由。

前提与不承诺：
- 电脑必须醒着。守护进程随系统睡眠停下，醒来才补判；要准点响需要用户自己配置定时唤醒电源计划（要管理员权限），本通道不自动改系统电源设定。
- 音箱必须在线；只播一次，不做循环播放、不排队下一首。睡眠模式不阻止闹钟，但云端在线才有输出。
- 只证明音箱来取过文件并接受播放；现场是否真听到仍要人耳确认。

## 安装与管理

独立用户环境位于 `~/Library/Application Support/VoiceDeck/xiaoai`，不得复用或升级米家现有venv。MiService 3.0.1以独立可选依赖安装，调用其账号/音箱接口；上游来源为[Yonsm/MiService](https://github.com/Yonsm/MiService)，已安装包元数据为MIT；aiohttp 3.13.2元数据为Apache-2.0 AND MIT。没有把上游SDK或账号凭据打入PocketDesk App。

```sh
uv venv --python 3.12 "$HOME/Library/Application Support/VoiceDeck/xiaoai/venv"
uv pip install --python "$HOME/Library/Application Support/VoiceDeck/xiaoai/venv/bin/python" -r scripts/xiaoai/requirements.txt
"$HOME/Library/Application Support/VoiceDeck/xiaoai/venv/bin/python" -I -B scripts/xiaoai/manage.py bind --default remote
"$HOME/Library/Application Support/VoiceDeck/xiaoai/venv/bin/python" -I -B scripts/xiaoai/manage.py probe
"$HOME/Library/Application Support/VoiceDeck/xiaoai/venv/bin/python" -I -B scripts/xiaoai/manage.py install
```

安装复制已测试源码到私有runtime快照，以用户级 `dev.pocketdesk.xiaoai` LaunchAgent启动，不重启PocketDesk或修改远端工作台。`status`读取脱敏阶段；`stop`持久停用并保留记录，重启电脑也不自动恢复，显式`install`才重新启用；`default local`或`default remote`保存默认选择，再`install`生效。音箱口述的目标选择仅影响该条请求。`restore-sleep`只恢复与绑定设备匹配的原睡眠值，不改音量或其他开关。
