# 一次发送多张图片

用户授权由主模型规划与独立验收，GPT-5.6 低推理强度执行实现。

## 交互与边界

沿用首页图片入口，通过系统文件选择器一次选多张。选择后按返回顺序显示缩略图，每张可移除；再次选择可追加。文字和图片由现有发送按钮一次提交，提交期间冻结附件编辑。取消选择不改变原草稿。

上传失败保留本地选择和文字，再次发送时可以重新上传。图片还未处理或上传完成时不能提前提交。损坏图片与超限情况明确提示，不静默丢图或截断。

原生“图库选择、预览、发送”路径参考 [Google 信息官方说明](https://support.google.com/messages/answer/6159880?hl=zh-Hans)。该来源证明既有入口流程，不证明 UU 远程的多图粘贴兼容性。本轮不新增相册面板、独立发送入口或图片管理页面。

## 数据流

浏览器压缩图片，每张独立上传，避免多张 base64 共用一个 HTTP 请求超出当前 12 MiB 限制。批次与图片身份随提交发送，服务端按明确顺序取图，不再依赖会被后续上传覆盖的全局单图槽。同一图片的上传重试不得重复追加。

发送前验证批次完整性与图片可解码性，再沿用本轮草稿绑定和焦点保护。桌面依次粘贴每张图片，最后执行一次 Return；不会按每张图片重复输入正文。Chrome 多图继续逐张写剪贴板和 Cmd+V，每张写入后等待 250ms 再粘贴，粘贴后等待 2.5s；若还有下一张，则在发送开始时记录的鼠标位置模拟一次左键点击并等待 180ms，以重建飞书网页编辑器的附件插入点。传统编辑元素不可见时，InputBinding 保留建立本轮时聚焦的 AXWebArea 作为页面边界；鼠标命中必须属于该 WebArea 或已绑定编辑元素的后代，且目标进程、前台、令牌和范围仍有效，因此飞书文档/表格可用，而 Chrome 地址栏、标签栏、其他页面或应用不通过。单图、原生飞书、UU 和无 InputBinding 的旧 `/send` 沿用既有路径。应用层仍无法读取飞书 DOM 或确认缩略图挂载，附件上传完成需真机确认。

`POST /api/image` 新请求为 `{batchId,imageId,data}`，兼容旧 `{data}`。`POST /api/live-input` 提交携带 `imageBatchId` 和有序 `imageIds`，继续兼容旧 `usePendingImage` 标记。旧 `/api/send` 保持单图协议，不扩展新批次字段。

每批最多 8 张，压缩后每张不超过 8 MiB（base64 后仍低于 HTTP 12 MiB），每批不超过 40 MiB，全局暂存不超过 80 MiB，15 分钟过期。上传重试复用图片身份，不重复占用条目；执行器的批次状态与图片资源统一管理。

## 失败与验证

上传阶段失败可重试；进入桌面粘贴后如果焦点变化或执行结果不确定，停手并要求检查电脑内容，不自动重放。已完成的同草稿提交沿用现有去重回执。

一旦图片执行已开始，服务端会拒绝同草稿身份重放。用户显式切换目标或失败后再次点击当前目标时，前端保留正文、附件批次与上传状态，但清空旧轮次的定时器、排队快照、失败态和输入上下文，生成新的草稿身份；应用激活完成后，已有正文立即以当前电脑输入位置建立新绑定，纯图片在发送时建立。健康状态重复点击当前目标不重建，避免 selection 模式把整段正文再次追加；键盘方向键只移动选中，电脑前台自动跟随也不重建草稿。

验收覆盖多选与追加、移除保序、上传等待、失败保留与重新上传、独立批次不串图、重复上传幂等、图片校验与限额、旧请求兼容、提交后去重以及部分执行失败停止。浏览器模拟接口验证前端，Swift 隔离测试验证服务端状态；真实目标应用的多图收件结果单独标注，不能用测试通过替代。

## 本轮验证结果

- `tests/multi_image_browser.py`：真实文件输入验证三选二保序、上传失败保留重试、图文及纯图等待压缩、八张移除后补选，以及图片防重放失败后重复点击当前目标/切到 Chrome 均更换草稿与队列身份且保留正文附件；8 次预期提交、46 次模拟上传，零页面脚本错误。
- `tests/workspace_browser.py`：原有输入/全屏回归通过，34 次模拟输入请求。
- `tests/image-batch-store.test.swift`：批次隔离、幂等与排序、重复/缺失图片拒绝、数量和单图体积越界、损坏图与消费后不可读取通过。
- `tests/image-paste-policy.test.swift`：Chrome 多图的 250ms 剪贴板稳定、2.5s 网页消费等待和仅在非末张后要求 180ms 插入点点击通过；Group/StaticText 焦点可归一到最近 WebArea，传统输入框取自身，工具栏角色链拒绝。Chrome 单图、原生飞书和 UU 仍为既有节奏，真实鼠标事件未在测试中执行。
- Swift 全量编译、输入队列与锁屏 Node 回归、差异格式检查通过。
- 已通过项目安装脚本更新并重启 `~/Applications/PocketDesk.app`；代码签名验证通过。直连回环 HTTP 读回确认首页多选标记、批次脚本及提交字段为新版，安装目录的四个改动 Web 文件与工作区一致，状态接口返回辅助功能已授权。
- 逐图粘贴及部分执行后的停止保护已作代码审查；未向真实第三方聊天发送测试消息，目标应用的附件接受结果仍须真机确认。
