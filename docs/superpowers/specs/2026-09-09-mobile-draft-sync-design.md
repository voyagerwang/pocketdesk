# 手机现有草稿同步设计

## 目标

手机输入框是本轮编辑的稿件来源。用户打开输入状态时，手机框内已经存在的整段文字也要同步到电脑当前输入框；之后手机上的新增、删除和修改继续实时反映到电脑，不能重复插入旧内容。

## 交互规则

1. 不新增同步按钮。聚焦手机输入框或打开全屏键盘时，自动建立本轮同步。
2. 手机输入框非空时，以手机全文作为本轮基线，并将电脑当前输入框对齐为这份全文。
3. 本轮建立后，手机每次编辑继续发送全文快照；电脑端根据同一基线只应用实际变化。
4. 手机输入框为空时沿用现有输入行为，不主动清空电脑已有内容。
5. 密码框、无法读取的编辑器以及 UU 特殊通道不做已有正文覆盖，继续使用原来的安全降级路径。

## 冲突保护

建立同步时先记录电脑输入框的元素、全文和选区。手机接管后，电脑内容必须仍与服务端上一份已确认快照一致；如果用户在电脑上同时修改、焦点切换或控制权变化，立即暂停手机同步并保留手机草稿，禁止静默覆盖或重复发送。

服务重启或同步会话丢失后，不凭手机全文猜测电脑状态。只有重新读取到同一输入框并重新建立基线，才恢复同步。

## 数据流

手机开始编辑时提交“采用手机全文”的一次性意图。服务端核验当前输入上下文，为草稿创建包含电脑原始快照和手机初始全文的事务；首次写入成功后，这份手机全文成为已确认基线。后续请求仍沿用现有草稿 ID，只发送最新全文，由同一事务计算并写入变化。

## 验收标准

- 手机框预先有“你好”，电脑空白：进入输入状态后电脑显示“你好”。
- 手机框预先有“你好”，随后改成“你好呀”：电脑最终显示“你好呀”，不会出现“你好你好呀”。
- 手机框预先有正文，电脑框也有旧正文：首次同步后电脑全文与手机一致。
- 同步期间在电脑手动改字：手机同步暂停、草稿保留，并提示用户核对。
- 首页和全屏使用同一规则；切换两种形态不会创建第二份草稿或重复输入。
- 输入法候选尚未结束时不提交半成品，候选确认后一次同步完整结果。

## 范围

本次只修正现有草稿同步协议与输入编排，不增加界面入口，不改变发送按钮、图片发送、显示器或触控手势。
