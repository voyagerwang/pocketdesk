# 小精灵：接着说与换件事
> L2 补充规格 | 父级: ../CLAUDE.md；实现地图: ../Sources/CLAUDE.md、../Web/CLAUDE.md

## 用户目标

用户看到未完成结果时，应能直接完成下一步，不必理解内部任务生命周期。手机首页、全屏工作台和电脑小精灵使用相同的动作含义；用户输入时能看见这一句话关联哪件事，并能保留草稿切换。

## 状态与动作

| 当前事实 | 主动作 | 行为 |
| --- | --- | --- |
| 暂时失败，完整记录可证明未执行副作用 | 再试一次 | 原任务补充一次明确继续请求 |
| 前置准备未完成，完整记录可证明未执行副作用 | 准备好了，继续 | 用户明确表示已准备后，原任务继续 |
| 缺少信息 | 补充信息 | 聚焦原输入框，保留前文 |
| 能力不覆盖 | 调整要求 | 聚焦原输入框，允许改变目标范围 |
| 已尝试发送或执行，结果尚未核实 | 核对结果 | 进入补充输入，不自动发送核对或重复操作 |
| 历史不足以证明可安全重试 | 继续处理 | 进入补充输入，保留执行事实 |

“换件事”始终是低强调出口，不与主操作平分注意力。重试旁可提供补充入口；已有草稿时优先展示补充输入，不能忽略草稿直接重试。

## 展示和输入

恢复卡保留最初用户目标的短摘要、具体问题和实际可行的下一步。删除每次都重复的保留/去重长说明；未知结果的必要核对说明仍保留。电脑恢复卡收紧，正常长回答继续使用宽版布局，球体保持原有底部锚点和表情规则。

补充时，输入框近旁显示“接着说 · 原目标”。换件事后收起旧失败卡，明确显示新输入归属并提供返回原事的入口；草稿和历史都保留。需要回答的问题和候选在补充时仍可参照，换件事才收起，返回时恢复。手机首页和全屏共享归属，不能出现首页显示继续、全屏只显示笼统收件人的情况。电脑显式点击补充后显示可编辑文本和光标，耳机仍使用原字幕模式，两种方式共用同一输入字段。

## 执行边界

`TaskRecovery` 依据结构化状态、台账和完整工具历史决定主动作，通过任务 JSON 同步给手机。失败状态本身不代表没有执行；未知记录和未知工具不推断为只读。旧客户端缺少动作字段时保守提供输入入口。

重试复用原任务 ID、上下文和持久操作证据，使用新的输入票据；连点、丢回包和跨端旧版本都复用原有幂等与 revision 边界。输入归属切换不清空待核对票据。重试提交的回执未知时，在两处输入旁显示“核对上次提交”，保留当前草稿并暂缓换件事；先只读查原票据，明确未找到才恢复完全相同的请求。即使轮询先收到执行状态也保留核对入口，旧revision回包不得回滚当前状态。显式补充和新事情跳过关系分类；普通耳机输入保留既有关系判断。

## 验证

隔离回归覆盖只读失败重试、写入/未知结果不提供一键重试、缺信息输入、带草稿切换、重复点按与回包未知。实际布局使用完整手机页面的网络替身和原生 AppKit 面板合成任务检查，不执行真实设备或外部消息操作。
