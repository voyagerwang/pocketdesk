> L2 补充规格 | 父级: ../CLAUDE.md；实现地图: ../Sources/CLAUDE.md、../scripts/CLAUDE.md

## 接口与依赖

采用 [Do1e/mijia-api](https://github.com/Do1e/mijia-api) 的 [mijiaAPI 5.0.0](https://pypi.org/project/mijiaAPI/5.0.0/)，Python 3.12 独立用户环境。v5 的设备规格参数是设备列表中的 `spec_type` URN，不能沿用旧版的 model。普通 CLI 输出和退出码不足以证明操作成功，因此 App 调用本项目 JSON 桥接器，桥接器调用固定版本 SDK 的底层 API。

上游声明 GPL-3.0，并在 README 标注非商业使用。本次用于用户本机个人接入；App 包只含本项目桥接脚本，SDK 单独安装，未复制上游源码。独立进程不代表已解决将来产品分发的许可问题，发行或商用前必须另行核对上游授权。

## 安装、授权与使用

打开 PocketDesk 电脑控制台 →「米家连接」→「连接米家」。页面生成短期二维码，用米家 App 扫码并在手机确认，App 核验账号后显示「已连接」。二维码可直接刷新或取消，过期自动撤下；「检查连接」仅核验现有授权，不自动发起登录。首次连接会在后台准备固定 SDK（需要本机已有 uv），失败会给出可重试提示。

两个 App 构建入口将 `mijia-bridge.py`、`mijia-network.py`、`mijia-policy.py`、`mijia-sensor.py` 与 `setup-mijia.sh` 打包至 `Contents/Resources/Mijia/`。开发调试仍可执行 `zsh scripts/setup-mijia.sh`；`--no-login` 只安装依赖。

独立环境在 `~/Library/Application Support/VoiceDeck/mijia/venv`，授权文件在同目录 `auth.json`；目录权限 0700、文件权限 0600。后台读取授权并验证，不打开登录、不索取密码、不把令牌或 SDK 原始日志传给模型；授权失效后在控制台重新扫码。显式登录可传 `--qr-path` 生成电脑可显示的二维码图片。

连接账号后，在同一卡片的「控制范围」选择一个家庭并保存；首次不会默认选择任何家庭，也没有「全部家庭」选项。可说“查看米家设备”“打开客厅灯”“把台灯亮度设为 60”“现在房间的湿度是多少”。仅查询已保存家庭中已适配的灯、开关及温湿度计：灯/开关按规格开放基础控制，温湿度计只读温度和相对湿度。摄像头、门锁、音箱、网关与未知类型暂不开放。必须使用唯一准确名称或返回的真实 ID，不能从相似名称猜设备。旧 miIO、没有 MIOT 规格或功能未开放的设备会给出具体限制，能否控制须以账号返回规格和真机回执为准。

模型仅能使用固定 `mijia` 工具的 status/list_devices/device_info/get_property/query_environment/set_property；兼容旧请求的场景与动作入口一律拒绝。安装和扫码不属于模型工具。可由本机环境指定 `POCKETDESK_MIJIA_PYTHON`、`POCKETDESK_MIJIA_AUTH`、`POCKETDESK_MIJIA_BRIDGE` 做隔离调试，模型参数不能指定这些路径。

## 单家庭范围

`GET /api/console/mijia/homes` 只向本机同源控制台提供家庭 ID/名称与当前选择，`POST /api/console/mijia/home` 接受一个 homeId，重新查询真实家庭清单后才保存。`home-scope.json` 位于米家私有目录、权限 0600，存家庭选择与账号标识的 SHA-256 摘要；账号登录本身仍是账号级授权，PocketDesk 在实际执行边界强制限定家庭。未选择、文件损坏或换账号后不查询/控制设备，不自动扩展至全部家庭。

Gateway 为设备查询、规格、属性和动作注入已保存家庭，模型传入其他家庭即拒绝。Python 对家庭接口的结果再次核对归属，缺失归属拒绝、其他家庭过滤，直接传入设备 ID 也不能绕过。准备完成后复核账号/家庭/选择版本，真正执行与范围保存及账号替换共用互斥锁，避免切换后迟到操作仍发往旧范围；网络和保存失败不抹掉既有选择。

SDK 场景列表只提供简表，场景的 home_id 由 SDK 按查询参数补充，不能证明内部动作的全部设备归属。因此场景名称不向模型提供，且禁止执行 run_scene；用户需在米家 App 内核对并运行。家庭 ID 不等于支持所有设备功能，查询结果和真实设备规格仍决定能力范围。

## 控制台扫码边界

`/api/console/mijia/` 与既有控制台共用回环、精确 Host、同源 Origin 边界；POST 必须带专用 JSON 请求头。状态仅含阶段/说明/会话 ID/期限/检查时间，二维码通过会话 PNG 端点读取且禁止缓存。二维码内容只允许 account.xiaomi.com 及其区域子域（如 sgp.account.xiaomi.com）的 HTTPS 登录路径，不返回轮询 URL、账号标识或令牌。

MijiaConnection 使用独立串行队列管理会话：显式 connect 检查依赖，必要时调用安装脚本；Python `--login-events` 输出立即 flush 的二维码事件和唯一终态。每次刷新创建新代际与私有暂存目录；完成后由 MijiaBridge 对暂存授权再次检查，成功才通过同目录 rename 原子替换正式 auth.json。取消/过期/失败保留旧授权，旧代际事件与迟到核验没有提交资格。登录进程和依赖安装有时限，页面隐藏时停止轮询并撤下图片，恢复只读查账。

## 准备、占用、执行与回执

读操作返回脱敏的设备/家庭/房间归属、真实规格和属性值；不回传设备 token、MAC、IP 或账号用户 ID。温湿度 source=device 才是本次设备直读，source=cloud 是历史上报；updated_at 为可信上报Unix秒或null，observed_at 是本次读取时间，两者不可混用。灯/开关 get_property 保留SDK原有的云端优先读取。允许的属性使用 `siid.piid` 定位，值按真实类型、范围、步长和枚举校验；`mijia-policy.py` 交叉核对原始 MIOT 设备、服务、属性URN及访问权限，仅允许灯/开关标准通断和灯亮度、标准温湿度传感器只读数值；另核验温湿度单位，拒绝字符串与全部动作。

业务调用直接使用实际家庭/设备接口验证账号，不再先查询无关消息；显式检查连接通过真实家庭清单核验。一次调用内复用 SDK 的家庭 owner 查询，并仅从已取得的指定家庭 `roomlist[].dids` 补全唯一房间名称，不增加请求、不丢弃未分房设备。设备清单的 online 只是云端标记；模型不知道准确名称时先列完整家庭清单，无法确认灯与开关关系时询问用户，不能试开来猜。

`mijia-network.py` 只缓存固定 MIOT 公开规格端点，完整 URN 是缓存键；同次调用共享成功响应和失败结果，避免按动作数重复失败请求。成功公开规格在 `mijia/spec-cache/` 原子保存，目录 0700、文件 0600，七天有效、最大 1 MiB，URN/格式/期限/权限不符即回源；缓存失败不影响实时响应，网络失败不落盘。家庭、设备、属性和控制请求不跨调用缓存；执行前依然重新核实设备属于所选家庭。错误文案区分家庭清单、设备清单、规格、属性、控制接口与确切的云端设备离线码，不把所有失败归因于用户网络。

写操作先调用只读 prepare，得到规范化真实目标与参数，Swift 再核验租约，在 TaskStore 锁内持久保存 pending。执行阶段重新核对目标与规范化请求，变化则零写入拒绝。名称和 ID 别名生成同一操作摘要；旧快照、进程重载和补充任务不能清除 pending 或已确认回执。同一任务相同操作只执行一次，新任务可以表达新的控制意图。

属性写后只追加一次设备直接读取核验，不重发写指令。当前值与目标一致才报告核实；网关接收、超时、读回不一致或回执结构未知都保留待核实，提示在米家 App 核对，结束本轮。动作和场景已由安全策略禁止；历史接受回执不能证明每台设备已完成。复合任务的明确成功回执可继续后续不同操作，未知结果封闭后续动作。

## 安全限制

2026-10-13 起，最小能力策略在列表、规格、读取、准备、执行与读回统一生效，敏感或未知设备即使直接传ID也不开放；名称与模型提示不能扩大权限。家庭是应用层范围，账号凭证仍是账号级授权，允许设备的名称/房间/基础属性会发给所配置模型。HTTP明文通道、同用户恶意程序及共享配对撤销的剩余风险见 [安全排查](security-audit-2026-10-13.md)，不能以扫码成功或0700/0600权限宣称整套系统安全。

## 温湿度准确性与查询速度（2026-10-13）

截图查询“现在房间的湿度是多少”耗时22.117秒，发生3次工具调用（设备列表、规格、属性）和4轮模型请求。64%来自云端记录，时间戳1786973041是Unix秒，北京时间为2026-08-17 21:24:01，已旧约56天；截图之后安装的安全白名单曾将传感器一并隐藏，本次按用户需要仅恢复标准只读温湿度。模型所说“刷新控制台即可看实时值”没有执行器依据，已明确禁止。

MijiaSensorQuery只识别完整、无页面上下文的首次环境读数句式，直接调用一次query_environment，免去模型往返；房间/家里等未指定准确位置的说法不猜设备，多台温湿度计必须选择。复杂、条件控制、跨家庭、历史比较、补充和多指标任务继续模型循环，同样可用综合查询。没有持久设备列表或读数缓存，查询重新验证所选家庭归属与标准规格。

依据[小米云端缓存与RPC文档](https://iot.mi.com/v2/new/doc/plugin/other/connection-wifi)，传感器online=true时尝试一次datasource=2直读；其余情况或直读失败只取一次datasource=3纯云缓存，避免默认datasource=1在无缓存时再次等待设备。online不是成功证据，必须核对逐属性回执和数值。没有可信上报时间就显示“更新时间未知”；云记录短答“客厅湿度当前值暂时读不到；最近记录64%（8月17日）”，保留当前查询未完成状态，不借本机查询时间制造新鲜度。
