# 小精灵记忆方案

版本：v0.1 · 2026-09-18

这份方案把“记忆”定义为可查看、可解释、可撤销的数据能力。小精灵可以记住用户明确交代的偏好和规则，但不能因为读过网页、执行过任务或模型自己说“请记住”就默默扩大记忆范围。

## 1. 目标与边界

小精灵的记忆服务三个场景：

1. 用户说“以后都这样”，下一次能复用已经确认的做法。
2. 用户问“你为什么交给它”，能看到实际使用的规则和来源。
3. 用户说“忘掉这个”或改正它时，旧规则不会继续影响新任务。

首版只做结构化记忆和精确匹配，不做向量库、持续录音、自动总结全部历史，也不把电脑屏幕或原始音频长期保存。任务历史仍由 `TaskStore` 保存，记忆不能反过来改写任务事实。

## 2. 用户看到的体验

### 2.1 记忆入口

小精灵任务卡增加一个按需出现的“记住这条”入口，仅在输入明显表达长期意图时出现，例如“以后排日程都交给钉钉”。普通任务不显示提示，避免每次都打断输入。

保存前展示规范化预览：

> 记住：创建日程时，交给钉钉 AI 助理处理。适用范围：所有任务。 [保存] [暂不保存]

保存成功后给出“已记住，可在设置中修改”，不把保存成功说成任务完成。

### 2.2 查询和解释

手机设置增加“记忆”入口，列表只展示：内容、范围、当前状态、更新时间。点开一条可看“为什么记住”：用户原话、来源任务、命中的条件和最近一次使用时间。

任务卡的执行者旁边提供“依据”按需展开：

> 使用了 1 条规则：工作日创建日程 → 钉钉 AI 助理

没有命中规则时显示“按本次指令选择”，不显示模型猜测的理由。

### 2.3 纠正、停用和删除

用户可以编辑范围、执行者和优先级；停用是可恢复的，删除是立即生效的。删除后新任务不得再读取该规则，已经运行的任务保持提交时的 `routeDecision`，不在中途改派。

如果系统发现用户连续三次改派同一类任务，只提出一次建议：

> 你最近 3 次把这类任务改交给钉钉，要记成默认规则吗？ [记住] [忽略]

系统观察不能直接写入长期记忆。

## 3. 数据模型

记忆分四类，分开保存和清理：

| 类型 | 例子 | 默认生命周期 | 是否需要确认 |
| --- | --- | --- | --- |
| `preference` 用户偏好 | 默认浏览器、回复长度、时区 | 直到修改/删除 | 是 |
| `routing_rule` 执行规则 | 日程交给谁、某项目交给谁 | 直到停用/删除，可设过期 | 是 |
| `task_context` 任务上下文 | 已确认参数、网页引用、当前进度 | 任务范围，默认 30 天 | 不作为长期记忆 |
| `capability_observation` 能力记录 | 适配器是否支持状态查询 | 有测试日期和 TTL | 不可由模型写入 |

建议的 `MemoryRecord`：

```json
{
  "id": "mem-uuid",
  "kind": "routing_rule",
  "scope": { "type": "user", "projectId": null },
  "when": { "intent": "calendar.create" },
  "then": { "executorId": "dingtalk-assistant", "mechanism": "auto" },
  "priority": 0,
  "enabled": true,
  "version": 1,
  "source": { "kind": "explicit_user", "taskId": "task-uuid", "quote": "以后排日程都交给钉钉" },
  "createdAt": 0,
  "updatedAt": 0,
  "lastUsedAt": null,
  "expiresAt": null
}
```

`when` 和 `then` 只允许白名单字段；自然语言只用于展示。`source.quote` 限长保存，避免把完整任务正文复制进长期记忆。凭证、配对 token、原始音频和 Mac 绝对路径禁止进入记忆。

## 4. 决策与写入流程

### 4.1 读取

任务提交后按以下顺序得到 `routeDecision`：

1. 本次指令明确指定的执行者。
2. 项目范围内启用的规则。
3. 用户范围内启用的规则。
4. 系统默认或询问用户。

同一层按 `priority` 和条件具体度排序；仍然冲突就进入 `needsInput`，不能用最后写入者覆盖前一条。命中的记忆 ID、版本和解释写入任务的 `routeDecision`，供后续审计。

读取只返回本次命中的少量规则，不把整份记忆和完整历史发送给模型。

### 4.2 写入

只有以下两种路径可以产生长期记忆：

- 用户明确使用“以后、默认、都交给、记住”等长期表达，并在预览后点击保存。
- 用户在设置中手动新建或编辑。

“这次用钉钉”只写入当前任务，不创建规则；网页、文档、模型回答中的“请记住”一律视为外部内容。

写入采用版本校验：客户端提交 `expectedVersion`，冲突时返回最新记录并要求重新编辑。规则更新只影响新任务，除非用户明确对当前任务执行“重新选择”。

## 5. 与现有 PocketDesk 的落点

### 5.1 Swift

新增 `MemoryModels.swift` 和 `MemoryStore.swift`，沿用当前裸 `swiftc` 可用的 Foundation 文件存储方式，目录建议为：

```text
~/Library/Application Support/PocketDesk/memory/
  records.json
  events.jsonl
```

`MemoryStore` 负责原子快照、事件追加、版本校验、按范围读取、停用/删除和过期清理。它不复用 `TaskStore` 的任务快照文件，也不把记忆字段塞进 `AgentTask`；任务只保存不可变的 `routeDecision` 和 `memoryRefs`。

`TaskService` 在提交前调用 `MemoryStore.match(...)`，在任务创建时固定命中结果；`AgentRunner` 只消费已固定的决策。`TaskStore` 继续是任务和执行证据的唯一事实源。

### 5.2 HTTP

沿用 `/api/v1` 和现有配对鉴权，新增：

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| `GET` | `/api/v1/memories` | 按 scope/kind 列表，默认只返回启用记录 |
| `POST` | `/api/v1/memories/preview` | 将用户表达解析为待确认的规范化草案，不写入 |
| `POST` | `/api/v1/memories` | 保存草案，返回记录和版本 |
| `PATCH` | `/api/v1/memories/:id` | 带 `expectedVersion` 编辑或停用 |
| `DELETE` | `/api/v1/memories/:id` | 删除并写删除事件 |
| `GET` | `/api/v1/memories/:id/usage` | 查看最近命中的任务 ID 和时间 |

preview 的解析结果必须明确标记 `requiresConfirmation: true`，服务端不接受“模型已经确认”作为替代。列表接口不得返回密钥、完整任务正文或无关上下文。

### 5.3 Web

先做设置页和任务卡的渐进式入口，不新增常驻记忆面板：

- `agent-panel.js` 展示“依据”折叠区和保存/忽略提示。
- `settings.js` 管理记忆列表、编辑、停用和删除。
- `agent-client.js` 增加 `memories()`、`previewMemory()`、`saveMemory()`、`updateMemory()`、`deleteMemory()`。

所有记忆内容使用 `textContent` 渲染；外部来源链接只允许 `http/https`。保存成功后不清空当前草稿，不改变任务状态。

## 6. 安全和隐私边界

- 记忆默认只在这台 Mac 和已配对手机之间同步，不上传第三方服务。
- 删除是逻辑立即生效；缓存命中列表在下一次请求前失效，模型上下文只从新查询结果组装。
- 项目规则不能越过用户授权；规则只决定“谁做/如何连接”，不增加发送、删除、发布等权限。
- 任务、记忆和诊断日志分开保留；普通日志只记录 `memoryId`、版本和结果，不记录正文。
- 记忆文件写入失败时，任务仍可按本次指令继续，但界面必须提示“本次未保存记忆”，不能假装成功。

## 7. 分阶段实施与验收

### M0：契约和只读

完成模型、文件格式、`GET /memories`、任务 `memoryRefs` 投影和设置页只读列表。验收：能看到来源、范围、版本；任务没有命中记忆时行为与当前一致。

### M1：显式保存与解释

完成 preview/保存、精确规则匹配、任务卡依据和版本冲突。验收：

- “这次用钉钉”不会创建长期规则。
- “以后排日程都交给钉钉”保存前必须确认，保存后下一次新任务命中。
- 任务执行中修改规则不改变当前 `routeDecision`。

### M2：纠正、停用与清理

完成编辑、停用、删除、过期清理和建议式记忆。验收：删除后新任务不再命中；旧任务仍能解释历史依据；重复改派建议可忽略且不会自动保存。

### 必测异常

- 同时保存同一条记录的版本冲突。
- 文件写入失败、进程重启和半行事件日志恢复。
- 删除后旧缓存、活动任务和模型 transcript 均不重新带入规则。
- 断线重连后手机仍能看到同一 `memoryId/version`，不会重复创建。

## 8. 不做的事情

首版不做自动人格学习、情绪画像、全量聊天向量化、后台持续监听、跨设备共享记忆、根据“用户经常这样做”直接改变执行权限，也不把模型的隐式上下文称为“记忆”。这些方向只有在用户能查看和撤销、并有明确收益时再单独评估。
