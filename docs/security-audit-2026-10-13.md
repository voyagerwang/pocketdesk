# PocketDesk 米家与本机入口安全排查
> L2 补充报告 | 父级: ../CLAUDE.md；实现地图: ../Sources/CLAUDE.md、../scripts/CLAUDE.md

## 结论与范围

后续范围补充：用户要求准确、快速查询室内湿度后，新增标准温湿度传感器只读能力。仍须同家庭锁、精确设备/服务/属性URN、单位和有限数值范围共同授权，即使规格可写也不开放写入。摄像头等敏感类型、动作和场景继续禁止；具体实现与测试见[米家接入](mijia-integration.md)。下文“仅灯/开关”记录的是本次扩展前的安全部署时点。

当前版本不能宣称满足含家庭摄像头场景的高安全要求。本次发现并修复了实际访问控制缺口，但普通手机工作台仍使用 HTTP/WS，米家凭证仍是账号级本机明文文件。此次是源码审查、隔离攻击用例与本机服务验证，不是完整第三方渗透测试或入侵取证；不能据此证明过去没有被利用，也不能承诺绝不会被攻破。

审查对象包括 HTTP/控制 WS/画面 WS、手机配对、米家扫码和凭证持久化、单家庭隔离、模型工具及敏感设备能力。未向模型、工具输出或日志暴露正式凭证；经用户确认的配对轮换只在本机进程内存使用新旧值并立即作失效核验。未操作真实家电、摄像头或门锁，未使用正确 WS 凭证接管控制或采集画面，未扫描公网或路由器。

## 已确认的问题与修复

| 风险 | 修复前证据及前提 | 本次修复 |
| --- | --- | --- |
| 高：配对二维码泄露长期权限 | 同一网络能访问服务的未配对客户端，GET `/api/qr` 返回 200 PNG，图片含长期配对令牌；只读现场检查未解码或记录令牌 | 二维码仅可信回环来源可读；精确 Host/Origin 和 Fetch Metadata 边界，阻止未知域、跨站图片读取；CORP、禁止嵌入与无 Referer 响应头 |
| 高：本机连接被过度信任 | 恶意 Host/Origin 的本机 status 请求返回 200 且含配对网址；控制/画面 WS 原代码接受任意字符串令牌加回环地址 | HTTP 统一校验实际主机和来源；本机写入豁免限同源 JSON；控制与画面连接一律验证真实令牌，不因回环免认证 |
| 高：泛化米家能力缺少隐私边界 | 隔离规格可让摄像头隐私模式写入、音箱文本动作执行、字符串属性原样返回模型；这些是合成 PoC，并非断言用户设备实际开放相同接口 | 仅允许标准 MIOT 灯/开关类型及基础属性；摄像头、门锁、音箱、网关及未知类型隐藏并拒绝直接 ID；通用动作与场景禁止；字符串属性不返回模型 |
| 中：配对令牌对其他本机用户可读 | 现场权限为 VoiceDeck 目录 0755、token 文件 0644 | 启动时原值保留，目录收紧 0700、文件 0600；无跟随链接描述符访问，拒绝硬链、非普通文件和异常内容；首次原子创建，失败不启用空凭证 |
| 中：未配对状态读取 | 远程可读前台应用、路径、动作日志等信息 | status、focus-probe、apps、recipients 远程读取要求 Bearer；手机启动和心跳补齐鉴权和非 200 处理 |
| 中：图标路径穿越 | 图标 ID 直接拼入磁盘路径，可构造目录外 PNG 路径 | 读写均限制安全 ID，目标必须已配置，不接受路径分隔符或编码逃逸 |
| 可用性：畸形报文 | 负 Content-Length 可形成非法数组切片；未对旧服务执行崩溃探测 | 严格非负有界长度，拒绝重复关键头及 Transfer-Encoding，进入业务路由前返回 400 |

安全策略放在可测试的 `HTTPRequestSecurity`、`Auth` 与 `mijia-policy.py`；模型提示和界面说明仅解释政策，不承担授权。米家 prepare 与真正执行重新检查设备类型、完整规格身份、服务/属性标准编号及读写权限；写后读回仅返回符合允许类型的值。未确认写入的原有去重与不重发边界保留。

本轮米家能力明确收窄为灯的开关/亮度、开关的通断。未知设备不会因为名称含“灯”或“开关”而获得权限；被隐藏设备和场景的名称也不发给模型。小米账号本身仍能返回整户设备清单，桥接层处理后只向模型提供允许的子集。

## 尚未解决的高安全要求

1. **手机传输仍有明文路径。** HTTP/WS 的长期令牌、输入和画面可受同网窃听或中间人攻击。HTTPS/WSS 通道已存在，但没有完成普通工作台的强制迁移及可信电脑身份验证；不能通过忽略证书警告解决。高安全使用需要验证身份的加密通道，并禁止敏感能力退回 HTTP。[OWASP 传输安全要求](https://cheatsheetseries.owasp.org/cheatsheets/Web_Service_Security_Cheat_Sheet.html)
2. **米家仍是账号级凭证。** “时光”属于本应用的执行策略，不是小米服务端为这份凭证签发的最小权限。窃取 `auth.json` 或在同一 macOS 用户下执行恶意代码，可绕过本应用策略。0700/0600 不等于加密，也不抵御同用户恶意程序；后续应评估系统钥匙串与能限制设备授权的官方接入。
3. **旧配对凭证可能已经泄露。** 本次修复访问路径和文件权限不会撤销已被复制的旧值。凭证轮换会使现有手机需重新扫码，旧配对主体的任务/待收文件不可见但不删除，需用户知情后执行。用户已明确同意，本轮已完成配对凭证轮换并重启服务；只读检查确认旧凭证401、新凭证200。现有手机需重新扫码，任务/待收文件未删除。当前仍是安装级共享长期凭证，缺少逐手机撤销及短期会话能力。
4. **模型与物理接线仍有边界。** 允许的设备名称、房间及属性会发送给配置的外部模型并可能保存在任务历史。最小工具权限限制了提示注入后果，尚未建立不可伪造的人类操作确认。标准开关也可能给摄像头或其他敏感设备供电，软件不能从 MIOT 类型推断接线。米家工具的拒绝并不构成整台电脑的沙盒隔离。
5. **依赖与发布尚未达到高安全产品要求。** SDK 固定 5.0.0，间接 Python 依赖未锁版本及哈希；SDK 请求默认验证 TLS，但登录返回地址和重定向尚未增加本应用逐跳网络目的地策略。当前是本机开发签名，不是完整正式发行、更新验证和供应链审计。
6. **公网可达性未验收。** 服务监听本机所有可用接口；没有排查路由器端口映射、IPv6 防火墙或进行外网探测，不能仅凭“局域网工具”认定公网不可达。不要把服务端口直接映射到公网。

## 验证记录

- Auth 29 项、HTTP策略 59 项、家庭范围 64 项、Gateway/Runner 51 项隔离检查通过；桥接65、最小能力策略21、网络21、扫码19、安装3项Python回归通过。
- 手机启动与心跳Bearer校验、恢复交互的完整浏览器替身通过，零真实桌面写入；米家范围/扫码、配对连接及相关手机Node回归通过。浏览器请求全部拦截为合成数据，不能替代手机真机通信验收。
- 完整生产构建、安装和代码签名核验通过；安装包4个米家脚本和本轮3个Web资源与源码逐字节一致。
- 安装后17项只读入口检查通过：合法本机控制台200；未配对LAN二维码403、状态/焦点401；伪造Host/Origin与跨站图片403；路径穿越404、负长度400；控制与画面WS错误令牌拒绝。没有使用正确WS令牌、接管控制或采集画面。
- 配对令牌已按用户确认轮换，独立只读任务接口确认旧值401、新值200；正式配对目录/文件现为0700/0600。未删除旧任务/文件或修改米家账号、家庭选择。
- 安装版对原来已选家庭的开关进行只读规格核验：仅保留标准布尔通断属性、动作为空；米家授权与家庭文件的inode/时间/尺寸/权限均未变化，未读取摄像头或发送设备写入。
- 本轮发现的是访问控制缺口，不是已经发生入侵的证明；过去是否被利用无法从这些验证确定。
