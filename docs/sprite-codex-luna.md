## 依赖与边界

- CodexModelClient 使用本机官方 CLI，先确认 ChatGPT 登录，再通过 exec 的临时会话和结构化输出生成一轮规划；不读取、复制或导出登录 token。子进程清除 API Key 与服务商地址覆盖，避免走另一份 API 账单。
- 单轮规划保留完整消息、工具描述与参数约束，仅去掉重复包装并无损解转义 JSON 回执；CodexModelProtocol 校验工具白名单和参数结构，转换成原有 ModelTurn。模型不能编造本机回执。
- 原生执行能力受 CLI 配置与只读沙箱约束；独立工作目录不含项目业务文件，客户端拒绝原生工具事件。Codex 仍读取本机全局 AGENTS 指令，结构化输出和规划指令约束本轮回复。模型只提出动作，AgentRunner 保持唯一工具执行循环，沿用控制租约、派单/发信去重和恢复语义。
- 完整 turn.completed、成功退出和有效结构化规划同时成立才向调用方返回成功；超时、登录失效、模型拒绝、无效参数或协议漂移都失败，无跨服务补发。
- TaskUsage 从零调用起点累计，保存可选 provider/model。任一请求失败或缺失用量则标 unknown；旧记录不补猜。统计表示本次执行尝试，服务商账单仍为计费事实。

## 2026-10-11 延迟与回执修正

用户真实任务耗时20.812秒，旧类似打开任务4.428秒，差异不能归因于搜索内容膨胀：新搜索结果仅2,720字节，旧样本4,409字节。Luna 同批提出 open_page 和 task_feedback，本机已返回打开请求回执，预写反馈却声称没有打开结果，导致错误终态。AgentToolBatch 现在保护事实顺序：首项反馈保留封闭后续动作的语义；实际工具之后的预写反馈必须依据真实回执再判断，准确单动作打开可封闭尾部反馈。13项顺序回归、原执行器、快速打开与48项恢复回归通过。

临时 model_catalog_json 从当前本机模型目录复制，仅关闭 Luna 的原生工具元数据，请求不再携带 exec/wait/apply_patch 包装；原关闭配置与只读沙箱保留。短时登录核验复用60秒，账号/程序元数据变化或失败即失效；路由器错误在 CLI 内部续轮之前终止。生产时序日志只有毫秒、字节、token与计数，不含正文或凭据。

同一历史上下文、31工具的旧/新两轮纯规划对照（不执行计划）：总耗时28.59到15.22秒，报告tokens75,960到26,413。这是各一次样本，模型返回计划不同，不能当整任务耗时或完成率验收。缓存、服务负载和采样会影响结果；旧CLI总计量不能确认其内部请求次数。

本地假供应商确认默认 analytics 造成约2.15秒的完成后退出等待；仅子进程 analytics.enabled=false 后降为7到8毫秒，不改用户全局设置。

最终版已重装。已安装服务的只回复文字任务5.492秒完成，无工具执行，保存来源codex/gpt-6-luna与12,742 tokens；当前真实时序为模型turn.completed 5,302ms、进程退出5,313ms，即退出尾约10ms，原生路由错误为0。登录核验38.7ms、进程启动0.3ms，剩余约5秒主要在等待模型回复，不能把冷启动或登录缓存宣传为主要收益。该文字任务不代表所有多轮任务都能5秒完成；准确单次打开仍沿用本机免模型路径。
