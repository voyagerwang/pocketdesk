## 2. 已确认的交互

### 出现与位置

- 手机首页或全屏工作台显式点选小精灵，显示桌面对话球；点击 Codex 等普通应用不触发。重复点选可重新展开，但不清草稿、不新建任务。
- 首次出现在当前鼠标所在显示器的可用区域中央，找不到则主屏；后续可拖动并记住位置。屏幕移除/分辨率改变后夹回可用区域。
- 自动展示不调用应用激活、不成为 key window、不挪鼠标、不抢输入框焦点。反馈窗默认无文本编辑器，手机保持唯一输入源。
- 切换到普通应用时收起整个反馈窗；后台任务照常进行，迟到结果不强行弹回或改变接收者。再次点小精灵恢复已保存的任务和当前草稿。
- 手动收起不取消任务、不删除草稿；进度更新不得自动把它展开。再次显式选择或点击收起态球球可展开。

### 构图与视觉

- 上方文字气泡，中间原有球球，下方一行状态。文字不压进球体，不让脸被挡住。
- 复用 Web/app.js 的现有完整 SVG 形象与 docs/orb-attribution.md 的归属声明；保留原始眼睛、路径和配色，只有整图轻动效，不单独变形眼睛，不重新生成角色。
- 如要提取共享素材，只保留一份权威资源，更新 Web 引用、打包脚本和相关地图。不要留下两套以后不同步的球球。
- 沿用 DESIGN.md 的经典蓝/米白身份与可读性原则。原生界面可使用系统字体和原生控件，不为它引入新的前端框架或远端脚本。
- 球球锚点稳定，短文气泡向上扩展；长文达到可用高度上限后滚动。用户翻阅时不强制滚到末尾；编辑草稿时让最新修订可见。
- 默认展示本轮问题和回复，历史折叠；新草稿与上一轮回答有明确标签，不能互相覆盖或看起来像同一条消息。
- 仅提供必要的收起、展开详情/历史操作。本版没有语音能力，不展示无效的朗读按钮。

### 状态与反馈

| 状态 | 文字与动效 | 真实触发依据 |
|---|---|---|
| 选中，空草稿 | 球球安静或轻呼吸；“你说，我在” | 显式选择 |
| 编辑 | 上方展示草稿，标“待发送” | 手机输入框快照 |
| 提交中 | “正在提交”，保留草稿 | 请求在途；不能提前写已接收 |
| 已接收/执行中 | “已接收”/“正在处理”，整球轻律动 | 服务端 accepted/running |
| 工具执行 | 可用时显示“正在读取页面”等 | 实际工具事件；没有事件就保持正在处理 |
| 待补充 | 完整问题与必要选项；停止忙碌动效 | needsInput |
| 完成 | 结论与完整结果入口；球球恢复静止 | 已持久化结果及证据 |
| 失败 | 失败原因和下一步；停止忙碌动效 | 真实失败 |
| 待核对/放弃等待 | 如实展示，不伪装成功或已取消 | verifying/abandoned |

“正在听”和麦克风声波不属于本版，因为手机听写没有提供可靠语音起止信号。“正在查找”只用于真的发生查找。只有真实任务接受后才能清空已发送草稿，发送失败继续保留。首版模型整段返回，不模拟逐字生成；没有百分比证据不画进度百分比。

追问继续走现有 supplement；已有任务执行时沿用现有 busy 规则，不为了动效开启另一轮执行。普通应用的共享草稿切换规则保持当前实现，点小精灵时可显示当前可见草稿，但绝不能把小精灵草稿注入普通应用。

外部派单：显示“已向 WorkBuddy 提交，尚未获得执行结果”；不能把小精灵本轮 succeeded 渲染成外部任务完成。结果优先使用持久化的 result/error 和真实派单回执，保留页面漂移提示等限定条件。

## 3. 数据与架构约束

先读 CLAUDE.md、Sources/CLAUDE.md、Web/CLAUDE.md、DESIGN.md，以及准备修改文件的 L3。现有改动很多，禁止 reset/checkout 覆盖其他工作的未提交内容。修改前检查当前代码，不根据旧方案猜实现。

已有链路：Web/agent-client.js、agent-panel.js、compose.js、app.js；Sources/AgentHTTP.swift、AgentModels.swift、TaskService.swift、TaskStore.swift、main.swift。复用现有提交事务、鉴权、控制租约、任务消息与事件；不创建第二套任务数据库或执行器。

建议职责边界：

1. **展示会话状态**：手机是否显式选中小精灵、当前草稿、草稿版本、提交中状态；为短期内存状态，不把每次听写修订写进任务历史。
2. **桌面反馈协调层**：合并展示会话与任务事实，决定可见内容和状态，不执行工具、不修改任务状态机。
3. **原生面板**：AppKit NSPanel 承载气泡与球球，主线程更新 UI；仅渲染与处理收起/拖动等界面操作。

如新增草稿展示接口，沿用现有 HTTP JSON/鉴权机制即可，不为展示再开端口。接口必须同时有：

- 使用服务端可核验的控制会话身份；观看者或失效租约不能改展示。
- 每次接收者选择的新代际、会话内递增序号和草稿版本；迟到输入不能覆盖新版，旧会话不能让已收起的球球复活。
- 草稿只展示不执行；一个在途请求加 latest-only 合并，最终发送使用完整正文，不能依赖最后一帧草稿已送达。
- 清空必须是显式事件；发送成功后的清空仅匹配提交时版本，不清掉用户刚输入的新草稿。
- 手机断线时标明输入连接状态，不能继续假装实时同步；Mac 已接收任务仍可完成并显示。重连同步当前快照而非回放所有按键。
- 不记录原始草稿到调试日志；锁屏隐藏正文，解锁后仅在符合当前显示意图时恢复，不弹历史通知。

任务状态由 TaskStore/TaskService 提供，按 taskId/revision/messageId 去重；持久化成功后通知 UI，回调不在存储锁内执行。轮询快照可以作为初版明确选择，但必须有活动期/静默期策略；优先复用进程内事件，不让 Mac 面板依赖手机轮询才能刷新。
