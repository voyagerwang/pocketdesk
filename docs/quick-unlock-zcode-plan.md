## 1. 目标与不可变边界

手机无需安装 CA、描述文件、VPN，无需忽略浏览器证书警告。首次 Mac 保存登录密码并确认配对；日常锁屏后手机点解锁，经通行密钥身份确认，由 Mac 本地提交密码给系统。密码仅进本机 Keychain，不传手机、云端、模型、日志、命令行、环境变量、剪贴板或草稿。
范围是 Mac 已登录、PocketDesk 仍运行且网络可达的日常锁屏。注销、重启后的 FileVault、Windows、唤醒离线电脑不属于首版。不能关闭系统锁屏或启用系统自动登录来替代实现。
选择：公开可信 HTTPS 网页入口 + Mac 主动建立的 WSS 出站连接 + 小型在线转发服务。解锁请求与状态走此入口；第一版不迁移视频流。公网不开放本机 HTTP 管理端口，不提供任意 HTTP 代理、命令执行或通用 RPC。
注意：可信 HTTPS 页面不能直接无缝调用现有 HTTP/自签 WSS 局域网接口；这会遇到混合内容、私网访问与证书边界。首版是独立解锁页，从原工作台用户点击进入；解锁后可明确返回已配对原工作台，只有原画面拿到新帧才能显示桌面恢复。不得承诺本期完整远控工作台自动无缝迁移。

## 3. 用户路径

首次：Mac 原生设置中主动开启快捷解锁 → 原生安全输入框保存密码 → 显示短期一次性配对二维码 → 手机进入可信网页注册通行密钥 → Mac 与手机显示相同配对核对码 → 用户在 Mac 明确确认该凭据 → 完成绑定。
不通过 HTTP 电脑控制台提交系统密码；即使回环也不因此绕过敏感设置认证。凭据修改/删除和配对授权通过本机原生入口处理。
日常：已配对页面收到新鲜 locked → 显示“电脑已锁屏 / 解锁电脑” → 点击触发 WebAuthn userVerification=required → Mac 独立验证 → 显示“正在解锁” → Mac 会话 confirmed unlocked 后显示“电脑已解锁”。原工作台恢复新帧之前仅显示“正在恢复画面”。
认证取消留在原页；离线、unknown、未配置密码、未配对分别给人话提示。密码提交后仍锁屏只能说“未确认解锁，请检查电脑”，不能凭超时断言密码错误。错误/超时无自动重试；确认凭据失效后提示在电脑更新。再次尝试必须由人点击并重新认证。
用户可在 Mac 撤销单个凭据、全部撤销、删除保存密码、关闭功能。关闭时立即使挑战/连接权限失效；注销与身份切换必须隔离。
通行密钥可能经平台账户同步；不能把它宣传为严格绑定某一台物理手机。UI 显示“已授权凭据/设备名称”，首版允许标准同步通行密钥，不要求硬件证明。不能承诺每次一定是 Face ID，实际系统可用面容、指纹或设备密码。

## 4. 组件与信任边界

Mac：LockStateMonitor（单一状态源）、UnlockCredentialStore（Keychain）、UnlockAuthorization（凭据及 WebAuthn 验证）、UnlockCoordinator（状态机）、UnlockRelayClient（出站 WSS）职责隔离；名称可按现有范式调整。复用 LockScreenInput 的输入能力和现有输入串行/租约边界，禁止复制另一套普通键盘执行器。不要把云端请求直接转成现有普通遥控 token。
服务端：设备连接鉴权、一次性配对会话、浏览器会话、严格白名单消息路由、限流与在线状态；只转发授权材料和最小状态，不接收系统密码，不长期积压解锁命令。不假冒 Mac 状态。
网页：可信单一 origin 提供配对、通行密钥认证、锁屏状态和结果页；不混用 localStorage 共享旧 origin。使用 HttpOnly/Secure/SameSite 会话 cookie、CSRF/Origin 检查、CSP、无第三方脚本；短期配对 token 用 fragment 承接后立即移除并安全交换，不进入日志/Referer。普通配对 token 不具备快捷解锁能力。
首选独立 relay/ 小模块承载 Node.js + TypeScript 服务、锁定依赖并记录实际版本，优先沿用仓库已有服务范式（若有）。Swift 验签用系统密码学实现，WebAuthn 数据解析优先成熟库；不手写密码学、不引入无来源依赖。浏览器可先复用零依赖 JS 风格，不另建复杂前端框架。

## 5. 配对与请求协议（实现时写版本化 schema）

Mac 持有独立设备身份私钥并放 Keychain。设备注册/路由身份须证明私钥持有；relay 不能仅凭可枚举 deviceId 接受连接。生产配置固定可信 origin/RP ID，不接受网络消息临时指定它们。
配对 token 至少 128-bit 随机、默认 5 分钟有效、一次消费、限流；Mac 生成注册 challenge，独立验证注册响应、绑定 credentialId 与公钥。配对核对码由双方实际登记的公钥/设备身份/会话 transcript 推导并在双方显示；不是 relay 任意生成的相同文字。用户在本机核对确认后才授予权限。已有 HTTP token 不允许远程添加解锁凭据。
Mac 生成至少 32 字节随机的解锁 challenge，并在本机登记 requestId/deviceId/账户会话/锁屏 epoch/credentialId/用途 unlock/连接代际/单调时钟到期时间（初值 30 秒）。所有影响授权的字段都绑定到该 challenge 的本机记录，不能由 relay 更改。
Mac 独立校验 clientDataJSON 原始字节对应的 type、challenge、允许 origin、跨源标志，authenticatorData 的 RP ID hash、UP/UV、算法和签名、凭据归属与撤销状态。验签输入按 WebAuthn 标准构造。counter 按同步凭据语义处理，不以始终单调递增作为唯一防重放策略。不把云端返回 verified=true 当认证结果。
验签后原子消费挑战，再执行一次；同一请求并发/重放均不可再次输入。断线、取消、锁屏 epoch/用户身份变化、撤销、超时立即作废。解锁命令不持久化、不排队到电脑恢复时执行；网络重试只能查询结果。
Mac 对状态与请求结果签名，带 boot/session/epoch/seq/requestId；手机依据配对确认的设备公钥验证，拒绝乱序与旧连接状态。服务端仍能拒绝服务，且托管网页被入侵可欺骗用户操作；不得宣传“服务端被攻陷也绝对安全”。
所有边界限制消息大小、结构/类型、频率和并发；错误信息不得带凭据或系统密码。

## 6. 锁屏事实与输入安全

状态 locked/unlocked/unknown 与连接 online/offline 分开。通知促发查询；初连、重连、提交前后主动查询。建议 5 秒心跳、15 秒无有效状态视为过期，参数集中定义。状态签名与序号不能代替新鲜度验证；浏览器从后台恢复先重新查询。
只有明确 locked、当前用户正确、Secure Event Input 与 AX 权限满足且凭据可用才能启用执行。明确 unlocked 的判断必须经平台适配器验证；通知与查询矛盾时 unknown。尽可能交叉验证，记录不含敏感信息的实机证据。
锁屏输入存在焦点/多账户/输入法/布局/Caps Lock 风险；现有“锁屏且安全输入”不能证明选中了正确账户密码框。G0 必须验证目标账户/密码框定位与支持布局；无法可靠确定就停止。先做全字符串可输入验证，再取出凭据并提交，逐键检查取消/代际。普通应用不能收到密码；本机同时解锁的竞争窗口必须实测并记录剩余风险。
Keychain 明确选择 macOS 支持的实现与访问控制，验证锁屏后可读取但不弹本机交互、应用升级/签名变化处理、睡眠恢复行为。禁止退化为明文磁盘或无限期内存缓存。不要禁用其他钥匙串的锁定保护。Swift String 不保证零化，减少副本及存活时间，不声称绝对擦除。
默认禁用，所有能力通过后用户主动启用。不把整个 HTTP 服务提到 root。若现有用户级路径在当前系统无法可靠注入，报告证据并完成其余独立模块，不能通过关闭系统安全功能“修好”。

## 8. 必须通过的验收矩阵

- 干净 iPhone/安卓浏览器首次扫码：零 CA 安装、零浏览器风险例外；可信网页和 WSS 均通过正常证书验证。
- 正确密码返回原用户桌面；发送按键只表示 sent，系统解锁与画面恢复是两个后续事实。
- 未配对/撤销/普通遥控 token/错误签名/origin/RP ID/UV 缺失/过期/错电脑/错会话/并发重放：输入执行次数必须为零。
- 服务端篡改 challenge/结果/状态或伪造 verified=true：Mac 不解锁；手机拒绝伪造状态（被攻陷网页本身不在此保证内）。
- 断线、Mac 睡眠、浏览器后台、服务端重启、手机换网、本机先解锁：无排队补发、无自动重复输入、旧状态不冒充实时。
- Keychain 拒绝/锁定、布局不支持、账户不符、辅助功能未授权、系统状态未知：拒绝输入；无临时明文持久化。
- 错密码/超时只产生一次提交；未确定原因不武断提示密码错；撤销后旧挑战立即失效。
- 请求/响应/日志/浏览器存储/异常报告中无系统密码；密码设置只能本机原生完成；远程管理代理无法到达本机管理 API。
- 旧语音草稿、图片、指针、视频和其他在做任务保持原边界。新增功能关闭或 relay 不可用不影响原功能。
