# 飞书口述收件者名称
> L2 | 父级: ./CLAUDE.md

小精灵将收件者类型交给 `kind`，用户明确给出的名称交给 `recipient`。例如“给名为7号的机器人发测试消息”可直接查询 `7号`；“7号机器人”“飞书指挥部”等边界不明确的称呼保留原词，由执行器先查完整名称。只有原词完整空结果时才补查 `7号` 或 `指挥部`，模型不得在首次查询前机械删词。飞书返回的真实名称本身含“飞书”“机器人”“群”时，保留完整名称。

## 确定性边界

- `FeishuMessaging` 先完整查询原词，已有结果沿用原候选；失败、分页或截断不通过改名掩盖。
- 仅机器人/群的完整空结果允许剥离有限边界语境词后补查一次，联系人姓名/邮箱不改写。群搜索的 `chats:null` 仅在同时明确数值 `total=0` 时视为空，缺字段和损坏结果不算空。补查前重新核对任务与控制权。
- 补查只在唯一候选与补查词准确同名时自动发送；多个候选或唯一近似名均展示候选并等待用户选择，冻结原正文与接收者类型，避免反复要求完整名称。空候选仍不发送。
- 不剥离名称中间的词，不改用联系人/群/机器人其他类型搜索，不复用历史 ID，不循环猜词。
- 选人、正文冻结、本人身份、发送前原子占用和未知结果不自动重试，沿用现有发送链路。
