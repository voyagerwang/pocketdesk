# 安卓原生直连快捷解锁 · 首版

用户决策：网页保留普通功能；高级能力安装 App。先安卓，后 iOS。不由产品方提供中转服务，也不要求用户准备域名、服务器或安装证书。

## 已实现边界

- Android 11（API 30）及以上；目前 target/compile API 35。单手机可保存一台电脑，电脑可配对并逐个撤销多台手机。
- 手机和 Mac 使用可互通的局域网 IPv4（10/8、172.16/12、192.168/16）。不支持蜂窝跨网、访客 Wi-Fi 隔离和 IPv6-only 网络；电脑需运行、已登录且可达。睡眠唤醒和 FileVault 开机登录不是本功能。
- 网页继续现有普通输入/控制/看屏能力，锁屏操作提示使用 App；App 不再展示会打开未鉴权地址的“普通网页”按钮；连接设置的帮助说明语音输入、触控板和画面仍通过浏览器扫描网页二维码使用。
- 电脑 App 启动时不再建立旧 relay 出站连接。旧 relay 与 WebAuthn 源码仅保留回归，不是当前用户入口。iOS 尚未创建客户端。

## 用户操作

1. 使用配套 Mac 测试版。先正常退出正在运行的旧 PocketDesk，再打开测试包；两版不能同时占用相同监听端口。原安装目录不会被构建脚本覆盖。测试包使用相同应用身份和本机设置/钥匙串，不是完全隔离的数据沙箱。
2. 电脑控制台打开“快捷解锁设置”，保存当前 Mac 用户的登录密码，开启功能。密码框保存后清空；HTTP 页面不能提交此密码。
3. 安卓安装 APK、连接同一局域网。App 点击“扫码连接电脑”，扫描电脑端“添加解锁设备”生成的邀请；相机不可用时可用“复制配对链接”与手机帮助中的“粘贴配对链接”。邀请五分钟有效，请只发给自己的手机。
4. 手机完成系统身份验证，两边显示相同七位核对码；只有用户在 Mac 上点击“确认配对”后才授权。手机点击“我已在电脑上确认”核验状态；返回 App 也只读刷新状态。新生成邀请会使前一个待确认邀请作废。
5. 用户手动锁屏，手机刷新状态，点击“解锁电脑”，再次完成手机系统验证。只有电脑确认锁屏状态已解除才显示已解锁；仅提交成功但状态未变化显示未确认，不自动重试。
6. 电脑 IP 变化可在手机中更新局域网 HTTPS 地址（默认 :46487），原证书指纹不变。电脑身份变化必须面对面重新配对，不能点“忽略证书”。
7. 电脑端可撤销单设备/全部设备、关闭功能、删除密码。手机“移除配对”删除本机私钥；电脑保留的登记应在电脑上另外撤销。

## 权限与证书

| 环节 | 用户可能看到的系统动作 | 说明 |
|---|---|---|
| 测试 APK 安装 | 允许文件管理器/浏览器安装未知应用 | 测试分发的安装来源确认；不是安装证书。正式商店分发另需发布签名与审核。 |
| 网络 | INTERNET 普通权限；系统/厂商另有联网或局域网限制时按设置开放 | 只访问扫码绑定的电脑，不扫描整个子网；目前 API 35 目标，不声称已完成未来 Android 权限变化适配。 |
| 相机 | 用户点扫码后才请求 CAMERA | ZXing 本机识别，无 Google Play Services 依赖，不上传画面；拒绝后用输入邀请。 |
| 手机身份验证 | 指纹/强生物识别或系统锁屏密码 | AndroidKeyStore 的每次操作授权签名，不能用 App 自绘密码框代替；未设置系统锁屏密码需先设置。 |
| Mac 输入 | 辅助功能授权 | 复用现有输入执行器；是否保留已有授权取决于签名/安装身份，测试版须实测。 |
| Mac 凭据 | 首次保存/访问可能出现钥匙串确认 | 后台读取禁止交互；锁屏取不到时失败，不弹窗等待、不重建设备密钥。 |
| 防火墙 | 如 Mac 防火墙阻止入站，需允许应用局域网连接 | 只开放应用，不要求关闭整机防火墙。 |

不请求定位、通讯录、存储、后台常驻、电池优化豁免、设备管理员、辅助功能（手机侧）或用户 CA 安装。Manifest 禁止明文网络和系统云备份。界面禁止截屏/最近任务预览以减少邀请暴露。

## 协议与密码边界

- 首次缺少身份时，Mac 自动在私有目录生成 TLS 叶证书/私钥；已有身份不静默轮换。没有生成/安装手机或系统 CA。证书指纹和电脑签名公钥通过电脑面前的二维码固定。
- Android 只在此应用连接中校验固定叶证书 SHA256 和有效期；拒绝未知身份、明文回退与 HTTP 重定向。不是全局 trust-all，也不关闭系统证书校验。TLS 私钥不离开 Mac。
- 手机生成 AndroidKeyStore P256 签名密钥，每次配对/解锁均要求系统认证；不导出私钥。首版不远程证明硬件安全级别，不声称所有安卓设备都具备硬件隔离。
- 邀请的 32 字节随机 pairId 只用于有效期内注册。注册返回的随机 credentialId 同时是 HTTPS 状态/挑战接口的持有凭证，保存在 App 私有存储中；不得写日志或暴露给普通网页。
- 注册签名消息为 UTF-8：`PocketDesk-Native-v1\npair\n<pairId>\n<challenge>\n<phonePublicKeyBase64url>`。
- 解锁签名消息为 UTF-8：`PocketDesk-Native-v1\nunlock\n<requestId>\n<challenge>\n<credentialId>`。ECDSA P256/SHA256、DER 签名；双方原生协议独立于 WebAuthn，不能混用挑战和凭据。
- Mac 生成 30 秒一次性挑战，绑定凭据、锁屏 epoch、当前用户与授权代际；验签成功后复用 LockScreenInput。逐键核验开关/撤销/连接/用户/锁屏/有效期；连接断开或条件变化中断后续输入。最多 64 个挑战，每分钟最多 120 次路由请求，全局只执行一次输入。
- Mac 登录密码只保存在本机钥匙串，手机从未接收它；系统验证授权的是手机密钥签名。读出密码后仅在本机提交窗口内使用。不保证 Swift String 可物理零化。
- 这不是防御电脑已被攻陷、手机系统被攻陷或用户确认了恶意设备的方案。首版也不保证每种安卓厂商的系统验证行为相同。

## 构建与验证入口

- 安卓：JDK 17、Android SDK platform 35/build-tools 35.0.0，`cd Android && ./gradlew assembleDebug testDebugUnitTest lintDebug`。Gradle Wrapper 固定发行包 SHA256。SDK 路径放 local.properties（忽略提交）。
- Mac 测试包：`bash scripts/build-android-test-host.sh`，生成 build/android-test/PocketDesk.app，不安装、不启动、不退出旧版本。
- Swift 回归：`bash tests/run-unlock-tests.sh`，包括原生授权与路由拒绝矩阵，真实系统输入均为替身。
- APK 的调试签名不等于可公开发布；正式发布需要稳定签名、商店材料和隐私说明。Mac 正式分发仍需 Developer ID/公证。

## 本轮实际验证结果

- Mac 全量编译与测试包签名验证通过，未安装/启动测试包。
- `assembleDebug testDebugUnitTest lintDebug` 退出 0：4 个协议单测 + 1 个真实 TLS 传输单测，全部通过，无跳过。TLS 使用本机回环临时证书/监听，真实局域网连接尚未验证。
- Android lint 无错误；固定证书 X509TrustManager 的通用安全提醒保留，明确由带外指纹验证及正反测试覆盖。不是忽略任意证书。
- `tests/run-unlock-tests.sh` 退出 0：既有授权/WebAuthn/relay 联调回归，以及新增 14 项原生授权检查和 10 项原生路由检查通过，真实锁屏与输入为替身。
- 网页 phone-settings/web-globals/live-recovery 回归通过，`git diff --check` 通过。
- APK 用 apksigner 验证签名通过；aapt 检查最终 Manifest 仅有 INTERNET、CAMERA、USE_BIOMETRIC 三项权限。
- Java 17、SDK 与 Gradle 安装在开发机缓存目录 `/Users/yz/.cache/pocketdesk-android`。首次下载 Gradle 使用镜像，并与官方发行 SHA256 核验一致；Wrapper 也固定此摘要。未改变系统 Java 默认路径。
- 诊断日志在 `/tmp/pd-android-final-build.log`、`/tmp/pd-final-unlock-tests.log`、`/tmp/pd-native-host-package.log`，未记录真实密码。
