# 耳机语音定位与统一取消

普通语音、小精灵唤醒与结束按语义处理，设备适配器只负责提供按下、松开、单击或长按。D95 音量动作、自定义操作与默认有线中键共用普通语音准备服务；默认有线减号和自定义唤醒共用小精灵接收层的取消裁决，不分别实现录音状态机。

普通语音先确认当前应用及原聚焦窗口，再定位输入框：当前普通编辑器优先；光标在正文或容器时继续寻找语义明确或完整扫描后唯一的普通 TextArea/TextField。搜索、密码、只读编辑器、多个候选或不可读分支不盲选。AX 聚焦或经真实命中校验点击后读回同一编辑器及未改动原文，准备成功才发送 Option；准备期间切应用、换窗口、松开或取消，迟到回调不发键。应用归属缺值补证必须有即时进程及系统控件的交叉证据，窗口层序不授权输入。

有线中键保留“按住说、松开结束”：正常监听及操作租约就绪时，helper 核验该设备该 usage 被接管后，原始按下立即进入准备，松开结束；松开早于准备完成则取消，不回补录音。原生键盘 Option 不拦截。默认来源只存在内存，不改用户规则；对应应用的自定义规则优先。未确认接管的整轮保持原生直通，不能按住期间切换映射；新连接须收到不早于 attachment 的健康回执。双击只在首轮实际准备接收框仍相同且来源/PID/代际未改变时请求发送，手动输入清理候选。

已有小精灵输入时，再次操作唤醒键即取消；默认有线减号短按也能取消，消费整轮按压，不因后续长按阈值、脉冲或松开重新录音。自定义单击、双击和长按唤醒同样先走取消裁决。有线中键在小精灵输入框中接续时仍按住说、松开结束；旧唤醒松开不能结束新录音。

当前 D95 配置用音量减少信号唤醒小精灵，音量增加信号启动当前输入框语音。按用户的左右分工，左耳负责打开/取消，右耳负责语音开始/结束；其他设备以设置里的动作映射为准。

| 当前状态 | 小精灵唤醒操作（左耳） | 语音操作（右耳） |
| --- | --- | --- |
| 小精灵输入未打开 | 打开输入并启动语音 | 继续普通应用语音 |
| 正在核验焦点或等待豆包启动 | 取消输入并收起 | 等待当前启动，不重复发送快捷键 |

聆听期间浮层标题只显示“正在听”，不附加左耳取消、右耳结束或即将提交提醒；取消、结束、自动停顿及最终转写门禁继续沿用原行为。2026-10-12 此文案已随完整构建和签名验证后安装，安装二进制匹配验证包。

Esc 同样取消当前输入。文字停顿自动结束仍按当前设备设置执行。长按操作仍在松开时结束。上述取消针对尚未提交的输入；任务一旦交给 TaskService，继续沿用任务服务的生命周期。

取消是完整收尾：先使本轮提交与异步唤醒失效，沿用同一 HID 事件源释放 Option，保留原输入框焦点发送 Esc 请求豆包取消；至少下一次探测确认豆包语音条消失后才收起小精灵。语音条仍可见时仅补一次 Esc；1 秒仍未确认则保留提示，允许再次左耳或 Esc 明确重试，不自动反复发键。取消期间右耳保持等待，失焦或切应用后不向新焦点补发 Esc。未执行任务不会因取消时的迟到转写而提交。

收起接收框还须交还应用焦点。第一次打开接收框前保存真实外部焦点对应的应用，重试与接续不覆盖它；明确取消且豆包关闭确认后，仅在 PocketDesk 仍活跃、没有其他本机设置窗口接管焦点、原应用仍运行且系统焦点仍属于 PocketDesk 或暂为空时激活原应用。焦点核验在后台读取，返回主线程后再次检查接收代际；用户已切应用或开始新一轮时放弃归还。只恢复应用，不点击或修改旧输入框，下一次右耳语音继续走普通输入框核验。

启动证据与接收框可见分开：先核验原生接收框及系统焦点，再发送一次语音快捷键；只有豆包窗口或本轮文字变化可证明启动，已有补充原文不能作为证据。焦点准备最多等待 3 秒，确认后立即发快捷键；快捷键发出后 3 秒没有启动证据，就释放按住式快捷键，保留接收框并提示“语音键重试，唤醒键取消”。开关式快捷键未观察到启动时不盲发第二次点按，避免超时处理反而打开录音。

SpriteDesktopInput 裁决接续与取消，默认音量和自定义映射只接管其动作结果；接收层在结束、重试和取消时同步退休两个旧拥有者。异步焦点与旧长按松开回调核验录音代际，不能干扰新一轮。取消通过 SpriteFeedbackPanel 抑制同展示代际的迟到状态；新唤醒才重新放行。右耳接续先于普通语音的修饰键门禁，且始终使用同一小精灵接收框。

结束时即使文字尚为空，也保留原有最终转写等待；空白不会创建任务。提交继续要求同源接收框、完整文字、豆包窗口关闭与 0.6 秒稳定，避免丢失迟到尾字。
