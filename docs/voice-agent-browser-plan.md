## 1. 产品判断

PocketDesk 已有手机输入、桌面画面、键鼠执行与控制租约；tt-bridge 可以补充 Chrome 页面读取和操作。仍需接入支持程序化派单、结果回传与任务续接的 Agent runtime。浏览器桥不等于 Agent，也不等于语音识别服务。

目标体验：手机交代工作，电脑执行，手机返回有来源的结果，随时查看画面和人工接管。首版沿用手机系统键盘听写；按发送后执行，识别中的草稿不触发动作。

## 3. 一个输入框的交互契约

- 一个输入框，清楚标识接收者：默认「AI 助手」，选中应用后显示「输入到：应用名」。模式只因用户明确操作改变，不能靠模型猜测将普通输入变成系统执行。
- AI 模式的草稿停留在手机；只有提交才进入任务服务，绝不经过现有实时输入链路写入前台应用。
- 当前页面以可见上下文标签表示，显示标题和域名；提交时绑定浏览器、窗口、tabId、URL 与观察时间。执行前重新核验，目标漂移时停止或澄清。
- 输入框上方只有当前任务卡：阶段、简短结果、来源、补充、停止、查看画面。历史任务按需展开。
- 追问携带明确 taskId 和结果引用；「第二个」「继续」不得重新猜测归属。
- 打断首版使用可见停止按钮；语音说停属于后续连续语音阶段，不能在首版承诺全天候可用。

## 4. 职责与数据流

```text
手机统一输入框
  ├─ 输入到应用 → 现有草稿/提交执行链路
  └─ AI 助手 → Mac 任务服务 → Agent runtime
                                ├─ BrowserAdapter → tt-bridge → Chrome
                                └─ 受控桌面工具 → 现有 PocketDesk 执行层
         ↑ 任务状态、摘要、来源、产物与补充要求 ↓
```

BrowserAdapter 是工具适配器，不是新的任务调度器。由 Agent 决定读取和操作步骤；PocketDesk 负责身份、目标、范围、控制仲裁及结果展示。首版只接一个 Agent、一个浏览器，串行执行。

手机不直连 tt-bridge daemon；模型凭证只在 Mac。任务事件和持久状态沿整体方案实现，不塞进光标 latest-only 队列或现有短期 ExecutionLog。

拟议最小能力：observe、read、act、capture，以及可用性声明。每次调用携带 taskId、目标引用与控制代际；实际参数必须以技术验证后的接口为准。使用结构化参数启动 CLI，不拼接任意 shell。

## 5. 优先场景

| 优先级 | 场景 | 用户价值 | 验收证据 |
|---|---|---|---|
| P0 | 总结当前网页，继续追问 | 不用复制链接或来回切应用 | 手机摘要、原网页链接、同任务续接 |
| P1 | 对比用户选定的几个网页 | 语音指定比较维度 | 每个结论可追到指定来源 |
| P1 | 填写当前表单草稿 | 减少手机和电脑间重复输入 | 读回实际字段；提交动作按授权范围处理 |
| P2 | 执行网页工作流，中途接管 | 复用 PocketDesk 远程控制优势 | 接管后 Agent 不再写入，续跑重新观察 |
| P2 | 从网页整理资料到指定系统 | 阅读到产物完整闭环 | 真实产物链接或目标系统记录 ID |

具备可靠原生 API 的目标系统优先使用 API；浏览器用于缺少接口或需要用户当前页面上下文的流程。

## 6. 分阶段交付

### M0：验证两条独立接口

1. 浏览器桥：人工安装的测试环境中验证状态、指定标签页读取、中文页面、切换页面、扩展断线和恢复；审查本地服务鉴权及许可证。
2. Agent：确认一种受支持的派单接口，能取得任务身份、返回结果、继续对话、报告错误和取消能力。现有 Codex 对话工具不是 PocketDesk 自动获得的集成接口。
3. 两项任一未通过，不宣称完成集成。仅向桌面聊天框粘贴任务最多算「已投递」。

### M1：只读闭环

单一输入框增加显式接收者；实现创建任务、查询结果、补充要求及最小持久状态。实现当前网页总结和追问。手机断线重连能找回同一任务；网页读取失败明确展示原因。

验收：选取中文文章、长页面、登录页面各类样本，总计至少 10 个任务；记录成功率、响应时间、成本或 unknown。页面切换不得读错目标，重复提交不得重复创建任务，模型回复不能冒充独立核验。

### M2：受控写入和人工接管

新增网页点击、填写和读取结果。现有手机租约不会天然约束 Chrome 扩展，必须将浏览器写入也纳入统一控制仲裁。停止后不再发新动作；在途动作是否已生效需要观察，不能承诺回滚。

对外发送、发布、删除按用户实际授权范围执行；缺少授权时先生成具体待执行内容，再请求一次确认。超时产生不确定结果时先核验，不自动重放提交。

### M3：连续语音与复用流程

在 M1/M2 数据证明可靠后加入独立 ASR、TTS、打断和经用户明确保存的流程。先验证手机浏览器录音、HTTPS、后台挂起与成本约束；不将全双工语音混进首版。

## 7. 品味与边界

保持输入工具原有快速路径；用一个入口连接明确职责。首版不建多 Agent 调度、不建向量记忆、不持续上传桌面画面。对用户保持简洁，对执行目标与证据保持明确。

下一步应执行 M0 技术验证，再决定运行时和浏览器适配器；不能先重做首页再发现结果无法回传。
