# 小精灵共享记忆与执行偏好方案

版本：v0.3 · 2026-09-19。状态：设计，未迁移生产数据。实施阶段引用主架构 G2。

## 1. 先说明已有能力，避免造第三套记忆

Workbench 已有两个不同来源：

| 来源 | 现状 | 迁移责任 |
|---|---|---|
| assistant_memory / assistant_memory_entries | 用户偏好、事实、Skill/任务偏好文字；按入口 profile 隔离，会话可绑定项目 | 保留身份/来源并补版本、范围、可撤销引用 |
| agent_execution_preferences | 单条 global 执行者/模型/费用偏好；临时整条指定 > 长期偏好 > 默认，登记任务已消费 | 纳入统一管理，保留确定性路由语义，不再新增第二套独立路由存储 |
| TaskStore / agent_tasks / execution events | 当前任务上下文、执行事实与历史 | 继续由任务系统维护，不迁进长期偏好表 |
| readiness / 本机权限与窗口状态 | 能力证据与实时环境 | 归能力观测或本机执行器，不允许模型改成用户偏好 |

统一的是模型、管理入口与决策规则，不要求立即把两个现有表物理合并。首版先用 MemoryService facade 包装两者，并在任务快照保留实际来源；有结构化表迁移时做单写切换。

PocketDesk 不新增可写 records.json / events.jsonl 长期记忆库。可保存只读 projection 与待提交草稿，离线不修改权威规则。

## 2. 产品行为

- Workbench 提供完整管理：普通偏好、执行偏好、项目范围、来源、历史版本、停用和删除。
- PocketDesk 提供相同服务的手机入口和当前任务“依据”，不维护另一份设置真相。
- 当前明确的“记住：……”以及设置页保存沿用现有显式授权，不因接入额外要求每次再确认。
- 系统推断、改派观察或从文章提取的候选，必须先展示规范化内容与范围，用户采用后才成为长期规则。
- 涉及扩大作用域/变更执行目标的模糊表达先澄清；“这次”只影响当前任务。
- 外部文档、网页、模型输出中的“请记住”不能成为授权。
- 已授权的 Skill 自动保存属于现有内容工作流，不等于允许模型自动修改长期路由或学习策略。本轮不改变它的授权规则。

## 3. 逻辑记录与版本

建议共享投影字段：memoryId、kind、principalRef、scopeType/scopeId、结构化 condition/action 或展示内容、status、version、sourceRef、createdAt/updatedAt、validFrom/expiresAt、lastUsedAt。

- kind 至少区分普通偏好、明确事实、执行规则；任务过程与能力观测不塞入长期记忆 CRUD。
- 自由文字只进入受预算限制的上下文，不自动编译成有权限的执行规则。
- 执行规则 condition/action 只用白名单，action 指向 capability/binding 建议，不能自带系统命令。
- 版本更新使用 expectedVersion；创建另有稳定 requestId，重复请求同内容返回同记录，不同内容报冲突。
- sourceRef 记录明确用户指令/设置保存/已采用候选及来源任务；原话限长、按留存政策保存。
- 凭证、配对 token、原始音频、无关屏幕正文不进记忆。设备路径使用受控项目/资源引用，不把路径当权限。

## 4. 路由消费与冲突

确定性优先级：本次明确指定 > 已准入项目规则 > 用户执行偏好 > 当前系统默认。项目规则是新增能力，需单独验收后启用，不能宣称现有 global 记录已支持。

保留现有“临时整条指定”行为：本次指定 Codex 时，不继承另一执行者偏好中的模型与费用组合。该语义若要改变，必须单独评审和回归。

同范围多条规则先按明确优先级与条件具体度；仍冲突则询问，不按最近写入覆盖。文本记忆说 WorkBuddy 而结构化执行偏好说 Codex 时，结构化规则决定路由，界面提示冲突并提供编辑入口，不能由模型偷偷选一条。

冲突职责：Workbench 的确定性规则解析层产生冲突投影，包含可访问的规则/记忆 ID 与版本、适用范围、当前生效规则及原因；Bridge 按主体权限转发，不另做路由决策；手机既有 Web 页面渲染说明和编辑入口，提交 expectedVersion 回到 Workbench。版本变化或冲突已消失时刷新投影，不按旧提示覆盖；离线仅展示缓存并标明过期，不允许本地更改共享规则。桌面反馈面板可展示简短冲突状态，当前不承担编辑入口。

命中结果仅提供建议，随后仍执行能力/费用/入口/项目权限检查。点名执行器不支持当前能力时明确阻塞，不静默改派。

任务记录 memoryId/version、来源类型、选定 binding 与解释。它固定历史决策，不固定未来权限；每次副作用重新核验实时授权。

## 5. 可信身份与迁移

1. 盘点两个存储来源及消费者，不批量把相同文本去重成跨用户记录。
2. workbench:owner 映射首个 canonical owner；旧入口 profile 仍隔离，跨入口 alias 须有可信绑定。
3. global 执行偏好是历史单用户假设下的存量，不无条件广播给所有微信/飞书用户。迁移先归 owner，明确绑定后共享。
4. 建 source-type/source-id → memoryId 的幂等映射；不重复创建；保留原来源和旧任务解释。
5. 先投影与影子比较，记录旧 resolver 与新 resolver 分歧；不实际双执行。
6. 分范围切换唯一写入者，旧 API 代理到新服务或明确只读；禁止两边继续独立写。
7. 完成版本/身份/删除回归后再让 PocketDesk 调用。失败时退回旧消费者，但保留迁移账本，不把旧表重新覆盖新记录。

## 6. 停用、删除与历史解释

区分两类操作：

- **停止使用/忘记规则**：权威服务立即停用或删除可检索条目，后续新决策不命中；已运行任务保留当时决策依据，不中途悄悄改派。
- **彻底删除内容**：清理原文、版本正文、缓存、可控检索与提示词组装源；审计仅保留必要 ID/时间/删除标志，历史解释可显示“依据已删除”。备份恢复必须重放删除记录，保留期限应向用户说明。

不能同时承诺“所有旧内容彻底消失”和“永久可查看旧原文”。用户若要停止在途动作，走任务取消/重新选择，而不是把删除偏好当作取消。

活动会话续轮重新组装记忆；检查历史 transcript 是否包含已撤销条目，不能只清列表仍把旧条目当有效指令重放。已提交给外部模型的请求无法事后撤回，应明确已发出与未来不再携带的边界。

离线缓存带版本/到期时间；无法确认新鲜度时只用于显示，不据此自动执行副作用。不承诺断网设备瞬时收到删除。

## 7. 数据发送与隐私

“本地存储”不等于“不会发送到模型”。界面说明命中的少量条目可能发送给当前配置的模型服务，明确发送范围与关闭选项；不发送整份记忆和完整历史。

所有查询按主体/项目/范围过滤；设备名不是主体凭据。来源引用、原话、日志按最小必要保存，普通诊断只记 ID/版本/结果。手机渲染沿用 textContent，来源 URL 限制协议并经过访问控制。

## 8. API 语义

沿用/扩展 Workbench 现有记忆与 execution-preferences 服务，PocketDesk 通过 Bridge 代理：列表、预览、显式保存、带版本更新、停用、删除、使用依据。具体路径在 G0 与现有 routes 对齐，不再先在 Swift 实现独立 CRUD。

preview 只返回候选，不写库；保存的依据必须来自用户指令或操作，不能由模型自报确认。权限、版本和幂等都在服务端校验，前端提示不代替校验。

## 9. 验收

- 旧显式记忆 CRUD、执行偏好优先级和任务消费不倒退。
- 同一可信 owner 两入口命中同一规则；未绑定渠道/其他项目不串用。
- “这次”不留长期记录，候选未经采用不生效。
- 同键保存重试不重复、并发更新冲突明确、迁移重跑不重复。
- 删除/停用后新决策不命中；旧任务保留允许留存的版本依据。
- 缓存过期/断网/重启/备份恢复不能复活已删除规则。
- 普通文字记忆与确定性路由冲突可见；记忆绝不扩大权限。
- 不支持的执行器明确受阻；临时指定不继承错误模型组合。

自动 Episode、夜间整理、经验试用/晋级及效果评估继续属于 Workbench S12/S13/S21 后续规划；本次统一不会把这些未完成能力标为已支持。

## 10. 人工分层管理的首批交付与后续

D-memory 隔离首版复用现有任务面板：长期记忆按四种现有类型搜索/过滤、编辑/停用/删除；执行规则单独管理现有 global 偏好；当前会话项目/任务上下文单独解释。原来源类型、更新时间、作用范围可见；修改携带内容指纹，事务内冲突拒绝。不是完整历史版本库，也未完成共享记忆迁移。

后续候选层必须把“待采纳建议”与有效记忆分开，提供来源、建议内容、范围、编辑后采纳/拒绝；候选未采纳不参与路由。打开目标规则另需结构化目标、匹配范围、优先级和真实消费测试；当前文字条目不能冒充该能力。界面保持人在回路中，不以自动学习为名扩大权限。
