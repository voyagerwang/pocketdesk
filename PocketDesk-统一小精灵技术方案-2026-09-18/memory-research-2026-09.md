# AI 记忆调研与统一方案结论

日期：2026-09-18

## 结论先行

PocketDesk 和 Workbench 应该统一为一个“助手记忆”体系，但不应该合并成一张不分层的聊天历史表。

推荐采用：**一个记忆事实源、一个管理入口、多个使用端、分层存储**。

- Workbench 负责长期记忆的管理、审计、跨设备同步和项目视图。
- PocketDesk 负责手机录入、Mac 本地执行和任务卡中的即时解释。
- 两端共享用户偏好、执行规则、来源、版本、范围和撤销状态。
- 当前设备能力、屏幕上下文、草稿、鼠标状态和临时网页绑定仍留在 PocketDesk。
- 工作台资料、主题、项目知识和产物引用仍留在 Workbench 知识/项目域。

最值得采纳的行业共性不是“让模型自动记住更多”，而是：**记忆可见、范围明确、来源可追溯、用户能纠正和删除，检索只带入当前任务真正需要的少量内容。**

## 1. 研究问题与证据边界

本次比较分为三类资料：

1. 学术论文：长时记忆的分层、检索、反思和遗忘机制。
2. 产品官方资料：用户如何查看、修改、删除、限制和隔离记忆。
3. Agent 记忆框架：记忆块、用户/会话/项目作用域、增删改查接口和时间有效性。

公开网页在本次环境中无法建立 DNS 连接，因此以下产品行为应在下一轮通过官方页面和实际产品逐项复核；论文结论依据公开论文的已知摘要和方法描述整理，不能替代原文逐段核验。

## 2. 论文与研究得到的共性

### 2.1 Generative Agents：观察、反思、规划分层

Park 等人的 *Generative Agents: Interactive Simulacra of Human Behavior*（UIST 2023）把 Agent 记忆拆成观察流、反思和规划。检索观察时综合相关性、重要性和新近性，而不是把全部历史塞进提示词。

对 PocketDesk 的启示：

- 任务过程是观察/事件，不等于长期偏好。
- “反思”只能生成候选记忆，不能直接获得用户授权。
- 记忆检索需要按当前意图和作用域过滤，并保留为什么命中的解释。

### 2.2 MemGPT：核心记忆与归档记忆分离

Packer 等人的 *MemGPT: Towards LLMs as Operating Systems*（2023）提出类似操作系统的虚拟上下文：少量核心记忆常驻上下文，大量历史放在可检索的归档区，由工具显式读写。

对本项目的启示：

- 当前任务、用户身份和少量稳定规则才进入核心上下文。
- 旧任务、长结果和资料引用放在按需检索层。
- 模型必须通过受控接口操作记忆，不能把提示词输出当作数据库写入。

### 2.3 MemoryBank：记忆需要更新和遗忘机制

*MemoryBank: Enhancing Large Language Models with Long-Term Memory*（2023）强调按时间和使用情况管理长期记忆，并讨论遗忘曲线和个性化检索。

对本项目的启示：

- 规则和事实不能永久保持最高优先级。
- 临时信息应有 TTL，设备状态应有测试日期和失效时间。
- “很久没用”可以降低检索优先级，但不能静默删除用户明确保存的规则；停用、过期和删除必须区分。

### 2.4 长期记忆综述的共同分类

近年的 LLM Agent 记忆综述通常把记忆分为工作记忆、短期/情景记忆、语义记忆和程序记忆，并从存储、检索、更新和遗忘四个环节评价系统。

对本项目的直接映射：

| 研究概念 | PocketDesk/Workbench 对应 | 是否长期共享 |
| --- | --- | --- |
| 工作记忆 | 当前输入、当前任务、待确认参数 | 否 |
| 情景记忆 | 已完成任务、执行结果、来源和回执 | 按任务保留 |
| 语义记忆 | 用户偏好、项目事实、已确认约束 | 是，需来源和范围 |
| 程序记忆 | “什么任务交给谁”“按什么流程执行” | 是，需显式授权 |
| 能力状态 | 某设备/适配器支持什么、何时验证 | 共享摘要，带 TTL |

## 3. 产品实践比较

### 3.1 ChatGPT：保存记忆与历史参考分开

公开产品说明中，ChatGPT 将用户明确保存的记忆与从历史对话中提取的个性化信息区分开，并提供设置入口查看、删除和关闭相关能力；临时对话用于不希望形成持续个性化的场景。

可借鉴：

- “保存的记忆”和“历史上下文”不能混成一类。
- 用户必须有总开关、单条删除和询问“你记得什么”的路径。
- 临时会话是产品能力，不是靠用户自己清空输入框来实现。

需要复核：不同账户、地区和版本的“参考聊天记录”能力及具体保留语义。

### 3.2 Claude：用户记忆与项目记忆分开

Claude 的公开说明强调记忆摘要和项目级隔离，用户可以查看、编辑或删除记忆，并通过不使用记忆的会话降低跨会话影响。

可借鉴：

- 项目记忆不能自动变成全局用户偏好。
- 管理页要显示记忆摘要和作用域，而不是只给一个“已开启”开关。
- 项目切换时必须明确当前会使用哪个作用域。

需要复核：项目记忆与用户记忆的优先级、更新触发和不同套餐的实际差异。

### 3.3 Letta/MemGPT：可编辑记忆块和显式工具

Letta 的 Agent 记忆模型把少量可编辑的 memory blocks 与归档检索区分开，模型通过工具更新记忆块。

可借鉴：

- 核心记忆要有稳定的槽位和大小边界。
- “用户信息”“Agent 人格”“项目规则”应分成不同块，避免互相污染。
- 每次写入都应是可观察的工具调用或服务事件。

不应直接照搬：让模型拥有自由编辑全部核心记忆。PocketDesk 涉及桌面控制和外部发送，写入必须经过服务端白名单与用户确认。

### 3.4 Mem0 等记忆服务：作用域和 CRUD 是基础能力

Mem0 等产品化记忆服务普遍提供按用户、会话、Agent 过滤的新增、检索、更新和删除，并将“记忆提取”和“记忆搜索”作为独立调用。

可借鉴：

- `userId / projectId / sessionId / agentId` 等作用域必须是一等字段。
- 删除和更新不能只改向量索引，还要改原始记录和缓存。
- 记忆服务不应替代任务系统或文档知识库。

需要复核：各服务的事实冲突、删除传播、租户隔离和数据留存承诺，不能只依据 SDK 的接口名称判断。

## 4. 对 PocketDesk 与 Workbench 的统一结论

### 4.1 统一的部分

两端共享同一个 `AssistantMemory` 逻辑模型：

```text
memoryId
kind
scope
condition
value/action
source
confidence
version
status
validFrom / expiresAt
lastUsedAt
createdAt / updatedAt
```

首批共享类型：

- 用户偏好：默认浏览器、时区、回复长度。
- 执行规则：某类任务交给哪个执行器。
- 项目规则：某个项目内的默认工作方式。
- 用户明确纠正：某个术语、联系人或工作流程的确认结果。

### 4.2 不统一的部分

以下内容不能成为跨端共享长期记忆：

- PocketDesk 当前屏幕、窗口、鼠标和输入焦点。
- 手机草稿、IME 组合态和附件上传中的临时状态。
- 设备权限、录屏授权、前台应用和控制租约的实时值。
- Workbench 的原始资料全文、知识库版本和项目产物。
- Agent 的完整 transcript、隐藏提示词和 API 凭证。

这些内容可以作为任务或资料的引用，但不能直接进入统一长期记忆。

### 4.3 统一管理入口

推荐入口是 Workbench 的“助手 → 记忆”，而不是在两个产品各放一套设置页：

- 全局视图：用户偏好和共享执行规则。
- 项目视图：当前项目的规则、纠正和资料关联。
- 设备视图：PocketDesk 本机能力与本地偏好。
- 任务视图：这次任务实际用了哪些记忆。

PocketDesk 的设置页保留“记忆”入口，但默认打开统一管理页；离线时显示只读缓存，并明确“离线修改将在重新连接后提交”，避免双写冲突。

## 5. 推荐的写入、更新和检索规范

### 写入

1. 用户明确表达长期意图。
2. 系统生成结构化预览。
3. 用户确认作用域、内容和执行影响。
4. 服务端白名单校验并写入事件。
5. 返回 `memoryId + version` 和可撤销入口。

模型、网页、文档和执行结果只能生成候选，不能直接写长期规则。

### 更新

- 使用版本号和 `expectedVersion` 做乐观并发控制。
- 编辑产生新版本，保留旧版本事件，不覆盖审计历史。
- 停用、过期、删除分别表达不同语义。
- 已运行任务固定当时的记忆版本。
- 冲突规则按本次明确指令 > 项目规则 > 用户规则 > 默认值处理；无法裁决就询问。
- 用户连续改派只能触发建议，不能自动升级为偏好。

### 检索

- 先按作用域和类型过滤，再按条件匹配。
- 只注入当前任务命中的少量记忆。
- 每条命中都返回 `memoryId/version/reason`。
- 低置信度、已过期和与当前项目无关的记忆不参与自动执行。
- 不用“相似度最高”代替权限和范围判断。

## 6. 适合本项目的验收标准

- 用户可以在一个入口看到两端共享的记忆，并区分全局、项目和设备范围。
- “这次使用钉钉”不会生成长期规则；“以后使用钉钉”必须确认后才生成。
- 删除共享规则后，PocketDesk 和 Workbench 的新任务都不再命中。
- PocketDesk 离线时不会创建第二份长期事实源。
- 任务详情能显示当时使用的记忆版本，即使后来规则已经修改或删除。
- 外部网页或模型输出中的“请记住”不会直接写入。
- 设备能力变化不会污染用户偏好。
- 删除能传播到缓存、检索索引和模型上下文组装层。
