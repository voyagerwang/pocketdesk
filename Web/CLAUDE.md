# Web/
整体甩送优化：识别器在相对握姿前翻之外，增加 280ms 内的短促加速度脉冲路径；相对重力增量至少 2.8m/s²，纯加速度需达到 4.2m/s² 峰值，步行级小振动不触发。当前传感器回调仍使用加速度合量，方向性由姿态/握姿门禁约束；真机需校准不同手机的加速度量程。
侧握甩送修复：gamma 限制改为相对当前握姿的侧向变化，起始侧倾不再直接拒绝；按 screen.orientation.angle（iOS 回退 window.orientation）映射横屏前翻轴，屏幕方向变化立即作废动作。依旧按转动幅度触发，不支持完全无转动的纯平移。diagnose.lastGesture 记录候选、调用提交及提交函数结束时间，finished 不代表第三方已送达。合成轨迹通过，真机侧握仍待验证。
甩送探测修复：必须收到两帧 beta/gamma/alpha 均有效的方向事件，仅加速度不算可用；disable/suspend 取消在途探测并作废迟到授权回调。unsupported 开关禁用并显示不可用说明。motion-send/settings 资源版本 3.1.5；真机手感仍需手机验证。

成员清单

index.html: 手机首页与非模态画面工作台；默认 PiP，全屏工具栏、菜单、始终可见的原生输入栏独立于图片变换。header 右侧是唯一设置入口（线条齿轮，44×44 触控区），设置面板为独立 `<dialog>`，与 `#screen-menu` 互斥且任一时刻只允许一个 dialog 为 open；窄屏 header 退化为稳定的两行 grid，不为塞入口而压缩字号或隐藏连接。classic scripts 按共享状态→控制/输入→设置→画面组件→工作台顺序加载，最后 boot。页面含实时同步状态落点 `#screen-input-status`（仅 error 态显示，由 compose.js 写入人话）与 `#live-flag`（常态/恢复进度，由 compose.js 写入“已同步 / 已恢复同步”等事后确认），两者供 compose.js 写、缺失其一都会让相应提示静默丢失（已被 `tests/live-recovery.test.cjs` 锁定）。
console.html: 电脑端控制台（自包含样式与脚本）。五步引导：系统授权（一键跳转设置）、手机扫码连接（局域网 QR + 安全连接 QR：后者内嵌 token，扫码即配对并拿到安全上下文，供翻腕发送使用；在线状态做成标题行右侧的 `.pill`，卡内不写说明文字——未探测到本机 TLS 身份就隐藏安全连接码，不诱导用户手装证书）、目标应用搜索/增删/排序/自定义图标 + 每个目标的设置展开区（默认打开输入框/触控板偏好、应用专属快捷键组、叠加全局组开关 showGlobal 默认开、内置常用快捷键下拉框 BUILTIN_PRESETS 一键添加刷新/粘贴/复制/撤销/回车/锁屏/关闭等）、快捷键管理（录制产出语义串 hotkey 如 "Cmd+Shift+Z"/"Return"：主键只认 event.code 物理键位、不回退 IME 可污染的 event.key，拦截 isComposing 与纯修饰键；录制器为作用域模型 recordCtx，全局与应用专属共用同一 keydown 监听，录完即存，反馈就地显示在触发按钮上；键位标签用 .keycap 样式、label 与键位展示重复时只显示一个，`hotkey` 为空的动作（「清空会话」）不渲染空键帽、提示串也不留孤立分隔符；支持重录/排序/删除）、最近动作（每 3 秒轮询 /api/status 的 log 字段，时间/结论徽章/动作+前台/说明四列网格，结论分三色：绿=已生效、琥珀=已发出未确认、红=未执行或失败——手机端点了没反应时来这里查第一现场）；默认经典蓝主题，:root[data-theme="muji"] 按需切换米白克制风；头部"经典蓝/米白"分段开关 POST /api/theme 写 Mac 本机，手机页自动跟随。**安全连接（HTTPS 地址 + CA 证书下载）整块已从控制台移除**——它就是用户点名要去掉的"大二维码"那张卡；免证书方案（3.0.30）后该向导整条删除：翻腕在环境不过关时整组隐藏，不再为它要求安装或信任 CA；`/PocketDesk-CA.cer` 服务端路由保留给锁屏 HTTPS 通道，不随翻腕降级一起删除。
app.js: 首页共享状态与启动/心跳编排、配对、历史、多图批次、快捷键与主题；目标渲染和选择事务委托 recipients.js。JPEG 原字节预览绕过 Canvas 黑图，其他图片缩放转 JPEG；切换事务与图片上传保持各自代际，迟到结果不能改动新目标。
console-agent.js: 电脑端「小精灵 · 模型服务」面板（控制台第 6 张卡，独立文件以免 console.html 继续膨胀）。三格配置 Base URL / 模型名 / API Key，保存与清空走 `/api/v1/model-config`，「测试连接」走 `/api/v1/model-test` 并用**输入框当前值**试跑（没保存也能先验证，填错不污染已保存配置）。Key 语义：留空 = 沿用已保存的值，要彻底清掉点「清空」。页面不缓存 Key、不写 localStorage、不进任何提示文案——服务端只回 `hasKey`/`keyHint`，输入框永远拿不回完整 Key。实测结果原样展示服务端证据（主机、模型、耗时、usage、文本回答、工具调用是否发起与最终回答），失败照实显示原因，不把「连上了但不支持工具调用」说成可用。

agent-client.js: 小精灵的任务客户端——只管与 Mac 的任务 API 对话，不碰输入区、不执行工具、不发桌面输入。requestId 是提交去重身份：**请求失败先按同一 requestId 查账再决定是否重试**，查不到才抛错，绝不盲发第二个任务。活动态与 Swift `TaskStatus.isActive` 同构；页面刷新先分页查找最新活动任务，再拉完整快照。轮询 2s 起、1.5 倍退避至 10s，有进展立即回到 2s。`send()` 是唯一发送入口：终态直接 `submit` 新任务、只有 `needsInput` 才 `followUp`、执行中直接报错——因此手机端不再有「新任务」按钮。detach 只解除手机与旧任务的关联，不删历史、不取消任务。
agent-panel.js: 小精灵的展示层——当前任务卡、结果、来源、当前网页绑定与可用动作。HTML 父层默认 `hidden` 防启动闪烁，渲染有任务且当前选中小精灵时必须显式解除，否则任务卡与放弃按钮会一起不可见。**所有文本一律 textContent 落地**，来源链接只放行 http/https。按钮是「放弃并保留草稿」而不是「停止」；runtime 不支持真中断，软超时只提示不假停止。
pad.js: 首页触控板与控制连接；认证/租约/序号及能力协商，观看者重新认证只领取空闲控制权且保留同 session 序号，移动可合并，离散事件先冲刷旧位移，断线清空不重放；断线与失去控制权时经 `syncMotionWithControl()` 调 `pocketdeskMotionSuspend()` 停翻腕识别，重新获得时调 `pocketdeskMotionResume()`。
settings.js: 手机设置唯一入口（header 齿轮）与底部模态面板；原生 `dialog.showModal()` 提供焦点限制与 Esc，遮罩点击按 dialog 自身判定不穿透，关闭后焦点回到齿轮且不自动弹键盘；触控板三控件由 `.pad-tuning` 整迁至此而 ID 与存储键不变，面板不复制第二份偏好；翻腕组 `#wrist-group` 默认 `hidden`，只有 `pocketdeskMotion.status()` 不是 `unsupported`（安全上下文 + 传感器接口都在）才显示——环境不过关时整组消失，不留灰色开关、证书下载或系统配置教程。组内只剩开关、一句 `#wrist-note` 说明与带度数的灵敏度档位；运动权限不再有独立按钮，而是在用户点开关的那次点按里由 `pocketdeskMotion.enable()` 一并请求，验证期间锁住开关避免重复弹权限，失败就地显示「暂时无法使用翻腕发送，请使用发送按钮」并把开关拨回关闭。翻腕偏好版本化且只存用户意愿，不持久化授权态或运行态；暴露 `pocketdeskSettingsOpen()` 供发送门禁查询、`pocketdeskMotionEnabled()` 供体感模块判断用户意愿（**不等于当前能跑**）。
compose-queue.js: 串行输入队列；生命周期主动取消用 ComposeCancelledError 拒绝未发送快照，compose.js 不把它当远端失败冻结；写入失败清队列仍按真实错误处理；仅同目标、同草稿 ID、同上下文的未发送快照可合并，每次提交独立完成；失败拒绝普通排队项，但保留同草稿已排队的显式删除，附 retry 核验原文，禁止跨目标或上下文恢复。
compose.js: 仅使用原生输入法；首页与全屏共享草稿 ID、整值/选区实时同步、特殊远控暂存、图文一次提交和 IME 恢复；提交等待图片处理及全批重传并冻结附件编辑，按有序 imageIds 绑定草稿；用户显式切换目标或失败后重选当前目标时，保留正文/附件并重建草稿身份、执行队列和输入上下文，激活完成后以当前电脑位置重新同步已有正文；健康状态重复点击不重建，键盘移动选中与前台自动跟随也不触发；保留电脑原文且不反填手机，手机只管理本轮段落；已有手机正文聚焦、页面返回、首次目标就绪或进入全屏即调度全文同步，候选结束补齐镜像，当前编辑面板而非焦点决定正文来源；通用模式持续上传全文，特殊远控暂存才停止预览请求，提交确认结束本轮（`clearCompose` 换新草稿身份，故下一轮首字即重新实时同步），失败暂停自动同步但保留显式发送路径，重试沿用草稿 ID/原目标并重新取输入上下文，保留首个真实失败原因；编辑框空白/实时同步/暂存均可见，44–88px 随文字增长，发送与关闭同排；原生长按由浏览器与系统输入法直接处理，不提供重复的粘贴按钮；Android 残留焦点自愈仅在短按 pointerup 执行，长按期间不 blur、不重建编辑元素；全屏上下文绑定控制会话与电脑输入位置，提交中冻结编辑，关闭取消未发送队列；首页/全屏清空保持草稿 ID 并上传空串，暂停后删除先核验；重建编辑元素并重绑事件，失焦取消 IME 超时探针，镜像始终读取当前首页框。`clearDraft()`（暴露为 `window.pocketdeskClearDraft`）是「清空会话」的手机侧本体：发带 `clear: true` 的幂等请求，**先让电脑侧确认删干净、成功后才 `clearCompose()` 清手机**——反过来的话，一次没生效的删除就把用户的草稿吃掉了（项目红线：失败必须保留草稿）；提交中或未选目标时拒绝并说明，文档类目标的豁免原因由服务端原样带回提示。

**跨弹窗安全恢复**（这一段是修"弹窗打断后只能切应用才能恢复"的地方）：失败回执带服务端 `state`，`pushLive` 的 catch 置 `livePaused` + `liveState` 并调 `startRecovery()`；此后**只发只读探测**（`probeLive()` 发送 `probe: true`），只有服务端回 `recoverable` 才解除冻结，随后走正常 `scheduleLive()` 按公共前缀补差量——**绝不重放正文**（`tests/live-recovery.test.cjs` 直接对 `probeLive` 函数体做否定断言，禁止它调用任何写入路径）。恢复触发来源有四条：页面回前台（`visibilitychange`）、窗口 `focus`、输入框/`#kb-proxy` 重新聚焦（`focusin` 捕获阶段，代理重建后仍有效）、以及 `RECOVERY_INTERVAL`（1.5s）低频有界探针，上限 `RECOVERY_MAX_ATTEMPTS`（20 ≈ 30s）后停下等用户事件。`scheduleProbe` 在 `liveProbing` 为真时把续期请求**登记**到 `recoveryPending`/`recoveryPendingDelay`，由 `probeLive` 的 `finally` 在探测落地后补排——早期版本在这里直接 `return`，恢复链在第一次探测后自己断掉，症状正是"只有切一次应用才能恢复"；`stopRecovery` 必须清空 pending，否则恢复成功后还会误续期。冻结期间 `pocketdeskCanMotionSend()` 返回 false，体感候选一律不发。`refreshInputContext` 对 Electron 提交后重建编辑器做有界重试（`CONTEXT_RETRY_LIMIT` × `CONTEXT_RETRY_DELAY`）。状态落点：错误人话写 `#screen-input-status`（仅 error 态显示），常态/恢复进度写 `#live-flag`。暴露 `pocketdeskComposeSend()`（复用同一业务锁的发送入口，**不是** pad.js 独占的 `pocketdeskSend`）、`pocketdeskHasDraft()`、`pocketdeskCanMotionSend()`（未选目标/发送中/提交锁/组合态/近 300ms 内有输入/`livePaused`/`liveProbing` 则 false）、`pocketdeskInputSettled()` 供体感发送门禁查询。`send()` 在 `selected === SPRITE_ID` 时整条转给 `sendToSprite()`：正文只交给任务 API，**不进电脑输入框、不写剪贴板、不调 /api/live-input**，服务端确认持久接收后才清草稿，失败保留正文。另导出 `window.pocketdeskFocusCompose`——无桌面副作用的聚焦路径，绕开 `showKeyboard()` 里的 `refreshInputContext()` 与 `scheduleLive()`（那会把还没发的 AI 指令同步到电脑）。
motion-recognizer.js: 翻腕手势纯函数识别器（无浏览器依赖，可 node 单测）；`makeRecognizer(params)` 从握姿基线启动限时前倾，达到角度立即发一次候选，不等待停稳或回弹，冷却且回位后重新武装；慢速换姿随动基线，不积攒角度；拒绝震动/扭转/转屏/无效姿态/数据缺口，角差按圆周计算，事件仅逐帧返回；阈值可配，不自动提高灵敏度；`isUsableSample(sample)` 判定传感器是否出数，有限数字（包括零）算有效，供能力探测使用。
motion-send.js: 翻腕发送的传感器侧；注册 `window.pocketdeskMotion`（环境/授权/数据/运行四级状态与起停）、`window.pocketdeskMotionSuspend/Resume`（控制通道挂起恢复）与 `window.pocketdeskWristAvailable()`（能力门禁，settings.js 委托它）。四级边界：环境层 `environment()` 判安全上下文与传感器接口，不过关即 `hidden`；授权层只在用户点按时调 `DeviceMotionEvent.requestPermission()`，绝不自动请求；数据层 `probeData()` 以 3 秒窗口等两个**有效**样本（`MotionRecognizer.isUsableSample`：有限数字即有效，静止的合法零值算通过，全 null/NaN 才算没数据）；三层都过才起识别器。它不再提供任何证书向导——`probeSecure`/`secureURL`/`caCertificatePath`/HTTPS 端口探测已全部删除。切后台、pagehide、断网、失去控制权一律 `suspend()` 并让 `dataVerified` 失效，恢复后 `resume()` 重新验证有效数据才起识别，不补发候选。每帧检查设置/草稿及 `pocketdeskCanMotionSend({requireSettled:false})` 场景门禁，组合输入/提交/冻结即清掉半途动作；输入静默 300ms 仅在候选完成时按默认门禁核验，通过后复用 `pocketdeskComposeSend()`，不排队补发。`diagnose()` 只回报环境与探测事实供真机基线使用，不触发桌面发送。
screen-geometry.js: 画面适应、1–6 倍缩放、包含横向旋转的坐标正反投影、位移换算和边界夹取；输入与光标只消费这一份几何，不混用 CSS 像素与桌面点。
screen-gestures.js: 触屏/指针/本地视野手势仲裁，兼容滚轮定位与结束相位；轻点、双击、合并触点采样/显示比例跟手滚动、按时间衰减惯性、捏合、按住放大瞄准及指针长按拖动，取消/第二指加入清理瞄准并松键，不补点击。
screen-pip.js: PiP 整块拖动、八向等比缩放、位置持久化和视口夹取；拖动中只写 transform，结束后保存位置。
screen-frames.js: 单帧请求与持续 JPEG 通道；解码呈现后 ACK，单请求在途、会话代际隔离、超时和降级，只有真实呈现更新画面时钟，停止后禁止交互重新启动采集。
screen.js: 工作台生命周期、小窗屏幕直选、显示器工具栏快捷轮换与菜单选择、默认点击/滚动统一、按需精确瞄准、四入口控制栏、菜单/右键/观看、控制权与画面新鲜度守卫；进入全屏尝试 landscape 方向锁，不支持时旋转画面坐标层；VisualViewport 重排；全屏固定页面并将首页设为 inert，退出恢复滚动位置；返回逐层收起，后台停止画面并释放手势。
style.css: 经典蓝设计令牌与首页基础布局；全局颜色/间距仍从此定义。
app-extras.css: 首页设置、历史、图片和快捷键后置规则，以及米白主题覆盖；加载在基础样式之后。
screen.css: PiP 与正立全屏网格；竖屏底部工具栏，横屏右侧工具栏，输入栏独立占位、输入时隐藏常规工具栏；根页面采用画面底色并隐藏首页，避免 Safari 键盘动画露出底层内容，画面坐标层支持自动横向旋转，内部图片进行缩放平移；瞄准镜与画面共用坐标层，显示真实画面的 3 倍局部。`#screen-input-status`（仅错误态）与 `#live-flag`（常态同步/恢复进度）同字号，后者更淡，只做事后确认不抢视线。

交互约束
