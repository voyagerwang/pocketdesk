成员清单

index.html: 手机首页与非模态画面工作台；默认 PiP，全屏工具栏、菜单、始终可见的原生输入栏独立于图片变换。header 右侧是唯一设置入口（线条齿轮，44×44 触控区），设置面板为独立 `<dialog>`，与 `#screen-menu` 互斥且任一时刻只允许一个 dialog 为 open；窄屏 header 退化为稳定的两行 grid，不为塞入口而压缩字号或隐藏连接。classic scripts 按共享状态→控制/输入→设置→画面组件→工作台顺序加载，最后 boot。页面含实时同步状态落点 `#screen-input-status`（仅 error 态显示，由 compose.js 写入人话）与 `#live-flag`（常态/恢复进度，由 compose.js 写入“已同步 / 已恢复同步”等事后确认），两者供 compose.js 写、缺失其一都会让相应提示静默丢失（已被 `tests/live-recovery.test.cjs` 锁定）。
console.html: 电脑端控制台（自包含样式与脚本）。五步引导：系统授权（一键跳转设置）、手机扫码连接（局域网 QR + 安全连接 QR：后者内嵌 token，扫码即配对并拿到安全上下文，供翻腕发送使用；在线状态做成标题行右侧的 `.pill`，卡内不写说明文字——未探测到本机 TLS 身份就隐藏安全连接码，不诱导用户手装证书）、目标应用搜索/增删/排序/自定义图标 + 每个目标的设置展开区（默认打开输入框/触控板偏好、应用专属快捷键组、叠加全局组开关 showGlobal 默认开、内置常用快捷键下拉框 BUILTIN_PRESETS 一键添加刷新/粘贴/复制/撤销/回车/锁屏/关闭等）、快捷键管理（录制产出语义串 hotkey 如 "Cmd+Shift+Z"/"Return"：主键只认 event.code 物理键位、不回退 IME 可污染的 event.key，拦截 isComposing 与纯修饰键；录制器为作用域模型 recordCtx，全局与应用专属共用同一 keydown 监听，录完即存，反馈就地显示在触发按钮上；键位标签用 .keycap 样式、label 与键位展示重复时只显示一个，`hotkey` 为空的动作（「清空会话」）不渲染空键帽、提示串也不留孤立分隔符；支持重录/排序/删除）、最近动作（每 3 秒轮询 /api/status 的 log 字段，时间/结论徽章/动作+前台/说明四列网格，结论分三色：绿=已生效、琥珀=已发出未确认、红=未执行或失败——手机端点了没反应时来这里查第一现场）；默认经典蓝主题，:root[data-theme="muji"] 按需切换米白克制风；头部"经典蓝/米白"分段开关 POST /api/theme 写 Mac 本机，手机页自动跟随。**安全连接（HTTPS 地址 + CA 证书下载）整块已从控制台移除**——它就是用户点名要去掉的"大二维码"那张卡；免证书方案（3.0.30）后该向导整条删除：翻腕在环境不过关时整组隐藏，不再为它要求安装或信任 CA；`/PocketDesk-CA.cer` 服务端路由保留给锁屏 HTTPS 通道，不随翻腕降级一起删除。
app.js: 小于 8MiB 的 JPEG 解码后保留原字节供预览和上传，绕过手机 Canvas 黑图并保留长图分辨率；其他图片缩放转 JPEG 前铺白底，转换异常拒绝处理。首页配对、目标、历史、多图选择/压缩/横向预览/幂等批次上传、快捷键与主题/前台跟随；提供其他经典脚本消费的共享状态，消息转发到全屏可见提示。维护**选择代际** `selectGeneration`：每次手动点选应用自增并带进 `/api/activate` 请求，回执代际与当前不一致就整条丢弃（不提示、不重建草稿）——A/B 快切时 A 的迟到回执不得改动 B 的面板、提示或同步。定位意图只在手动选择路径上显式传 `true`（`activateTarget(selected, true)`），自动跟随与隐式激活一律保持默认关闭。快捷键按钮条对 `draft.clear`（「清空会话」）走**本地分支**：调 `window.pocketdeskClearDraft()`，不投递任何按键、不进 `/api/shortcut-trigger`；`pocketdeskClearDraft` 缺失（页面装了半截）时如实报错，不做静默 no-op。
pad.js: 首页触控板与控制连接；认证/租约/序号及能力协商，观看者重新认证只领取空闲控制权且保留同 session 序号，移动可合并，离散事件先冲刷旧位移，断线清空不重放；断线与失去控制权时经 `syncMotionWithControl()` 调 `pocketdeskMotionSuspend()` 停翻腕识别，重新获得时调 `pocketdeskMotionResume()`。
settings.js: 手机设置唯一入口（header 齿轮）与底部模态面板；原生 `dialog.showModal()` 提供焦点限制与 Esc，遮罩点击按 dialog 自身判定不穿透，关闭后焦点回到齿轮且不自动弹键盘；触控板三控件由 `.pad-tuning` 整迁至此而 ID 与存储键不变，面板不复制第二份偏好；翻腕组 `#wrist-group` 默认 `hidden`，只有 `pocketdeskMotion.status()` 不是 `unsupported`（安全上下文 + 传感器接口都在）才显示——环境不过关时整组消失，不留灰色开关、证书下载或系统配置教程。组内只剩开关、一句 `#wrist-note` 说明与带度数的灵敏度档位；运动权限不再有独立按钮，而是在用户点开关的那次点按里由 `pocketdeskMotion.enable()` 一并请求，验证期间锁住开关避免重复弹权限，失败就地显示「暂时无法使用翻腕发送，请使用发送按钮」并把开关拨回关闭。翻腕偏好版本化且只存用户意愿，不持久化授权态或运行态；暴露 `pocketdeskSettingsOpen()` 供发送门禁查询、`pocketdeskMotionEnabled()` 供体感模块判断用户意愿（**不等于当前能跑**）。
compose-queue.js: 串行输入队列；仅同目标、同草稿 ID、同上下文的未发送快照可合并，每次提交独立完成；失败拒绝普通排队项，但保留同草稿已排队的显式删除，附 retry 核验原文，禁止跨目标或上下文恢复。
compose.js: 仅使用原生输入法；首页与全屏共享草稿 ID、整值/选区实时同步、特殊远控暂存、图文一次提交和 IME 恢复；提交等待图片处理及全批重传并冻结附件编辑，按有序 imageIds 绑定草稿；用户显式切换目标或失败后重选当前目标时，保留正文/附件并重建草稿身份、执行队列和输入上下文，激活完成后以当前电脑位置重新同步已有正文；健康状态重复点击不重建，键盘移动选中与前台自动跟随也不触发；保留电脑原文且不反填手机，手机只管理本轮段落；已有手机正文聚焦、页面返回、首次目标就绪或进入全屏即调度全文同步，候选结束补齐镜像，当前编辑面板而非焦点决定正文来源；通用模式持续上传全文，特殊远控暂存才停止预览请求，提交确认结束本轮（`clearCompose` 换新草稿身份，故下一轮首字即重新实时同步），失败暂停自动同步但保留显式发送路径，重试沿用草稿 ID/原目标并重新取输入上下文，保留首个真实失败原因；编辑框空白/实时同步/暂存均可见，44–88px 随文字增长，发送与关闭同排；全屏上下文绑定控制会话与电脑输入位置，提交中冻结编辑，关闭取消未发送队列；首页/全屏清空保持草稿 ID 并上传空串，暂停后删除先核验；重建编辑元素并重绑事件，失焦取消 IME 超时探针，镜像始终读取当前首页框。`clearDraft()`（暴露为 `window.pocketdeskClearDraft`）是「清空会话」的手机侧本体：发带 `clear: true` 的幂等请求，**先让电脑侧确认删干净、成功后才 `clearCompose()` 清手机**——反过来的话，一次没生效的删除就把用户的草稿吃掉了（项目红线：失败必须保留草稿）；提交中或未选目标时拒绝并说明，文档类目标的豁免原因由服务端原样带回提示。

**跨弹窗安全恢复**（这一段是修"弹窗打断后只能切应用才能恢复"的地方）：失败回执带服务端 `state`，`pushLive` 的 catch 置 `livePaused` + `liveState` 并调 `startRecovery()`；此后**只发只读探测**（`probeLive()` 发送 `probe: true`），只有服务端回 `recoverable` 才解除冻结，随后走正常 `scheduleLive()` 按公共前缀补差量——**绝不重放正文**（`tests/live-recovery.test.cjs` 直接对 `probeLive` 函数体做否定断言，禁止它调用任何写入路径）。恢复触发来源有四条：页面回前台（`visibilitychange`）、窗口 `focus`、输入框/`#kb-proxy` 重新聚焦（`focusin` 捕获阶段，代理重建后仍有效）、以及 `RECOVERY_INTERVAL`（1.5s）低频有界探针，上限 `RECOVERY_MAX_ATTEMPTS`（20 ≈ 30s）后停下等用户事件。`scheduleProbe` 在 `liveProbing` 为真时把续期请求**登记**到 `recoveryPending`/`recoveryPendingDelay`，由 `probeLive` 的 `finally` 在探测落地后补排——早期版本在这里直接 `return`，恢复链在第一次探测后自己断掉，症状正是"只有切一次应用才能恢复"；`stopRecovery` 必须清空 pending，否则恢复成功后还会误续期。冻结期间 `pocketdeskCanMotionSend()` 返回 false，体感候选一律不发。`refreshInputContext` 对 Electron 提交后重建编辑器做有界重试（`CONTEXT_RETRY_LIMIT` × `CONTEXT_RETRY_DELAY`）。状态落点：错误人话写 `#screen-input-status`（仅 error 态显示），常态/恢复进度写 `#live-flag`。暴露 `pocketdeskComposeSend()`（复用同一业务锁的发送入口，**不是** pad.js 独占的 `pocketdeskSend`）、`pocketdeskHasDraft()`、`pocketdeskCanMotionSend()`（未选目标/发送中/提交锁/组合态/近 700ms 内有输入/`livePaused`/`liveProbing` 则 false）、`pocketdeskInputSettled()` 供体感发送门禁查询。
motion-recognizer.js: 翻腕手势纯函数识别器（无浏览器依赖，可 node 单测）；`makeRecognizer(params)` 对“前倾并停住片刻”发候选，对震动/扭转/转屏/数据缺口一律拒绝；阈值全部可配，默认保守，不自动提高灵敏度；另有纯函数 `isUsableSample(sample)` 判定传感器是否真的在出数（有限数字即有效，静止的合法零值算通过，全 null/NaN 才算没数据），供免证书方案的"数据层"门禁使用并可直接 node 单测。
motion-send.js: 翻腕发送的传感器侧；注册 `window.pocketdeskMotion`（环境/授权/数据/运行四级状态与起停）、`window.pocketdeskMotionSuspend/Resume`（控制通道挂起恢复）与 `window.pocketdeskWristAvailable()`（能力门禁，settings.js 委托它）。四级边界：环境层 `environment()` 判安全上下文与传感器接口，不过关即 `hidden`；授权层只在用户点按时调 `DeviceMotionEvent.requestPermission()`，绝不自动请求；数据层 `probeData()` 以 3 秒窗口等两个**有效**样本（`MotionRecognizer.isUsableSample`：有限数字即有效，静止的合法零值算通过，全 null/NaN 才算没数据）；三层都过才起识别器。它不再提供任何证书向导——`probeSecure`/`secureURL`/`caCertificatePath`/HTTPS 端口探测已全部删除。切后台、pagehide、断网、失去控制权一律 `suspend()` 并让 `dataVerified` 失效，恢复后 `resume()` 重新验证有效数据才起识别，不补发候选。候选经 `pocketdeskCanMotionSend` 门禁后复用 `pocketdeskComposeSend()`。`diagnose()` 只回报环境与探测事实供真机基线使用，不触发桌面发送。
screen-geometry.js: 画面适应、1–6 倍缩放、包含横向旋转的坐标正反投影、位移换算和边界夹取；输入与光标只消费这一份几何，不混用 CSS 像素与桌面点。
screen-gestures.js: 触屏/指针/本地视野手势仲裁，兼容滚轮定位与结束相位；轻点、双击、合并触点采样/显示比例跟手滚动、按时间衰减惯性、捏合、按住放大瞄准及指针长按拖动，取消/第二指加入清理瞄准并松键，不补点击。
screen-pip.js: PiP 整块拖动、八向等比缩放、位置持久化和视口夹取；拖动中只写 transform，结束后保存位置。
screen-frames.js: 单帧请求与持续 JPEG 通道；解码呈现后 ACK，单请求在途、会话代际隔离、超时和降级，只有真实呈现更新画面时钟，停止后禁止交互重新启动采集。
screen.js: 工作台生命周期、小窗屏幕直选、显示器工具栏快捷轮换与菜单选择、默认点击/滚动统一、按需精确瞄准、四入口控制栏、菜单/右键/观看、控制权与画面新鲜度守卫；进入全屏尝试 landscape 方向锁，不支持时旋转画面坐标层；VisualViewport 重排；全屏固定页面并将首页设为 inert，退出恢复滚动位置；返回逐层收起，后台停止画面并释放手势。
style.css: 经典蓝设计令牌与首页基础布局；全局颜色/间距仍从此定义。
app-extras.css: 首页设置、历史、图片和快捷键后置规则，以及米白主题覆盖；加载在基础样式之后。
screen.css: PiP 与正立全屏网格；竖屏底部工具栏，横屏右侧工具栏，输入栏独立占位、输入时隐藏常规工具栏；根页面采用画面底色并隐藏首页，避免 Safari 键盘动画露出底层内容，画面坐标层支持自动横向旋转，内部图片进行缩放平移；瞄准镜与画面共用坐标层，显示真实画面的 3 倍局部。`#screen-input-status`（仅错误态）与 `#live-flag`（常态同步/恢复进度）同字号，后者更淡，只做事后确认不抢视线。

- 默认触屏：轻点点击、单指滑动滚动、双指缩放/平移；按住 450ms 显示 3 倍局部放大镜，移动按三分之一速度瞄准，松手才点击；双指轻点打开右键/一次性拖动菜单。指针模式在更多中按需切换，单指相对移动、双指滚动/轻点右键，不持久化为下次默认。
- 可见输入区始终正立。键盘已打开时点画面仅收起键盘，不能同时点击电脑；toggle 在 pointerdown 捕获状态，避免 blur 抢跑。
- PiP 常用按钮只显示全屏/关闭图标，28px 紧凑按钮，15px 图标；屏幕标签高 26px，语义保留在 aria-label/title。
- PiP 为观看/摆放入口，全屏承担直接操作；返回全屏→PiP→首页，草稿保留。

手机设置整合（3.0.23）：触控板内齿轮与 `.pad-tuning` 整体迁入 header 唯一入口 + 底部模态面板，旧 `show-tuning` 状态、`#pad-settings` 节点与 `padCard` 引用一并删除，`exitPadMode()` 不再顺手关面板。三个触控板控件的 ID、范围与 `pd-sens`/`pd-scroll`/`pd-ruler` 全部保留，读写仍在 pad.js。翻腕组以默认关闭的开关占位，未接入传感器前不提供可开启的假开关。

翻腕发送落地（3.0.24）：新增 motion-recognizer.js（纯识别器）与 motion-send.js（传感器侧），经 `scripts/setup-secure-channel.sh` 生成的自签 CA 在 :46487 提供 HTTPS，满足手机运动传感器要求的安全上下文。能力门禁 `pocketdeskWristAvailable()` 现返回真实能力（不支持/非 HTTPS/未授权各有对应原因）；用户开启后复用 compose.js 的 `send()`，受 `pocketdeskCanMotionSend` 门禁约束（设定期/无草稿/输入中/提交中/组合态不误发）。设置面板内提供 iOS 授权按钮、灵敏度预设与「练习（不发消息）」实时倾角条。阈值默认保守、需在真机标定，尚未经过 iPhone/vivo 双机正式验证。

翻腕标定读数（3.0.25）：灵敏度三档带度数直接写进下拉选项（随 `PRESETS` 自动同步），刻度条上画出阈值标记线；练习区改为大字实时倾角 + 「阈值 X° · 本次最大 Y°」读数，并区分「已触发 / 未发送：原因 / 等待抬起（需超过 X°）」。停止练习时给出结论（已达阈值可用 / 差几度或改调灵敏度），传感器不可用时直接说明原因而不是留一个永远不动的读数。灵敏度档位写入 `pd-motion-send` 的 `sens` 字段并在重新加载后灌回识别器；`updateWristUI()` 同时按偏好回填开关状态，避免刷新后开关显示与运行态不一致。settings.js 先于 motion-send.js 解析，故档位恢复放在 `DOMContentLoaded`。

主页输入框唤起键盘（3.0.26）：修掉安卓 Chrome「点输入框不弹键盘」的两个成因。其一，退出触控板模式原本挂在 textarea 的 `pointerdown` 上，会在一次点按尚未结束时就把输入框从 52px 撑回 140px，安卓据此判为无效点按、焦点拿不到；改为只在 `focus` 上退出触控板模式。其二，键盘被系统返回手势收走后 textarea 往往**仍是 activeElement**，焦点无变化时 Chrome 不再弹键盘；在 `pointerdown` 先交还焦点（`visualViewport.height` 比 `innerHeight` 低 120px 以上即视为键盘已展开，此时不动焦点以免打断点选光标），并在卡片上补一次 `click` 聚焦以覆盖点在内边距/空白处的情况。点按按钮、滑杆不抢焦点。

误发与重复输入修复（3.0.27）：`window.pocketdeskSend` 归 pad.js 独占（screen.js 的画面/指针指令通道），compose.js 的发送入口改注册为 `window.pocketdeskComposeSend`，motion-send.js 只认后者。此前 compose.js 在 pad.js 之后加载并覆盖同名全局，使画面里每一次点按、滚动与 `cursor-subscribe`/`take-control` 都转成 `send()`——表现为**没开翻腕也会自动发送**，且随画面可见性与 `auth_ok` 频繁触发。同时安卓专属的输入补丁由 `androidInputPatch`（`/Android/i` UA 判定）收口：残留焦点再聚焦、内边距补聚焦与 IME 卡死自愈三处都会对编辑框 blur→focus，iOS 上听写/输入法会因此把同一段内容再落一遍，表现为**重复输入**。新增 `tests/web-globals.test.cjs` 锁定该全局单一归属、加载顺序与平台门禁。

翻腕练习移除（3.0.28）：练习通道整套删除——页面上的「练习（不发消息）」按钮、大字倾角、阈值刻度条与 `#wrist-status` 一行，以及 `motion-send.js` 的 `startPractice/stopPractice/isPracticing` 与 `onSample` 回调。练习本是为真机标定阈值而设，但灵敏度三档已把度数写进选项（低 30°/中 22°/高 15°），读数面板只是把同一个数重复展示一遍，反而让设置面板越拉越长。翻腕发送只剩「活动监听」一条路径：开开关即监听，可用性原因就地写回 `#wrist-note`（未授权 iOS 仍显示授权按钮）。灵敏度档位与偏好行为不变。

证书获取与安全地址改为可点链接（3.0.29）：手机在明文地址下开启翻腕发送时，设置面板不再只给一段「请在手机浏览器访问 https://…:46487」的散文，而是渲染两个真正可点的整行链接——「① 安装 PocketDesk 证书」指向 `/PocketDesk-CA.cer`（刻意放在 HTTP 也能取到的路径：手机在信任证书之前只有 HTTP 可用；服务端新增该路由并用 `application/x-x509-ca-cert` 触发系统安装流程），「② 在安全地址打开」指向同主机的 `:46487` 且 `target="_blank"`（换新页去授权，路径与查询原样保留，不把用户丢回首页）。地址由 motion-send.js 以结构化字段给出（`secureURL()` 只换协议与端口），设置面板用 `createElement` 造 `<a>`、不拼 innerHTML。控制台第 2 步的四个地址（永久/IP/跨网/安全）同样由 `<span>` 改为可点 `<a>`，并新增「下载 PocketDesk 证书」入口。`tests/phone-settings.test.cjs` 锁定：地址不得再以散文形式出现、两端地址都必须是 `url-link` 链接、CA 路由与证书 MIME 必须存在。

免证书降级（3.0.30）：翻腕不再要求手机下载、安装或手动信任 CA。设置面板的四步证书向导（下载 `/PocketDesk-CA.cer` → 系统里安装 → 开启信任 → 探测后跳 `:46487`）整条删除，控制台安全连接整块保持移除；`/PocketDesk-CA.cer` 服务端路由保留给锁屏 HTTPS 通道，不随翻腕降级删除，也不删除用户已有证书与系统信任。环境不过关时 `#wrist-group` 整组隐藏，可用时组内只剩开关与灵敏度，权限并入开启那次点按；motion-send 改按 环境/授权/数据/运行 四级状态工作，以 3 秒窗口内的有效传感器样本（零值算通过）证明可用，切后台/断网/失去控制权挂起、恢复后重验。依据 `docs/wrist-send-no-certificate-plan.md` 阶段 2 与阶段 3（Mac 控制台 HTTPS 配对码）；阶段 1（真机基线）、4（发布验收）仍需双机实测。
