成员清单

index.html: 手机首页与非模态画面工作台；默认 PiP，全屏工具栏、菜单、始终可见的原生输入栏独立于图片变换。header 右侧是唯一设置入口（线条齿轮，44×44 触控区），设置面板为独立 `<dialog>`，与 `#screen-menu` 互斥且任一时刻只允许一个 dialog 为 open；窄屏 header 退化为稳定的两行 grid，不为塞入口而压缩字号或隐藏连接。classic scripts 按共享状态→控制/输入→设置→画面组件→工作台顺序加载，最后 boot。
console.html: 电脑端控制台（自包含样式与脚本）。五步引导：系统授权（一键跳转设置）、手机扫码连接（局域网 QR + 自动探测的 Tailscale 跨网 QR + 在线状态）、目标应用搜索/增删/排序/自定义图标 + 每个目标的设置展开区（默认打开输入框/触控板偏好、应用专属快捷键组、叠加全局组开关 showGlobal 默认开、内置常用快捷键下拉框 BUILTIN_PRESETS 一键添加刷新/粘贴/复制/撤销/回车/锁屏/关闭等）、快捷键管理（录制产出语义串 hotkey 如 "Cmd+Shift+Z"/"Return"：主键只认 event.code 物理键位、不回退 IME 可污染的 event.key，拦截 isComposing 与纯修饰键；录制器为作用域模型 recordCtx，全局与应用专属共用同一 keydown 监听，录完即存，反馈就地显示在触发按钮上；键位标签用 .keycap 样式、label 与键位展示重复时只显示一个；支持重录/排序/删除）、最近动作（每 3 秒轮询 /api/status 的 log 字段，时间/结论徽章/动作+前台/说明四列网格，结论分三色：绿=已生效、琥珀=已发出未确认、红=未执行或失败——手机端点了没反应时来这里查第一现场）；默认经典蓝主题，:root[data-theme="muji"] 按需切换米白克制风；头部"经典蓝/米白"分段开关 POST /api/theme 写 Mac 本机，手机页自动跟随。
app.js: 首页配对、目标、历史、多图选择/压缩/横向预览/幂等批次上传、快捷键与主题/前台跟随；提供其他经典脚本消费的共享状态，消息转发到全屏可见提示。
pad.js: 首页触控板与控制连接；认证/租约/序号及能力协商，观看者重新认证只领取空闲控制权且保留同 session 序号，移动可合并，离散事件先冲刷旧位移，断线清空不重放。
settings.js: 手机设置唯一入口（header 齿轮）与底部模态面板；原生 `dialog.showModal()` 提供焦点限制与 Esc，遮罩点击按 dialog 自身判定不穿透，关闭后焦点回到齿轮且不自动弹键盘；触控板三控件由 `.pad-tuning` 整迁至此而 ID 与存储键不变，面板不复制第二份偏好；翻腕组默认关闭，开关不写死 disabled——用户尝试开启后才就地显示不可用原因（能力由 `window.pocketdeskWristAvailable()` 提供）；翻腕详情区只有两项：「授权运动传感器」（仅 iOS 需一次点按触发 `DeviceMotionEvent.requestPermission`）与「灵敏度」预设（低/中/高，度数随 PRESETS 自动写进选项，仅调 liftDeg 与 holdMinMs），可用性原因就地写回 `#wrist-note`，不再提供练习读数面板；翻腕偏好版本化且只存用户意愿，不持久化授权态或运行态；暴露 `pocketdeskSettingsOpen()` 供发送门禁查询、`pocketdeskMotionEnabled()` 供体感模块判断是否开启。
compose-queue.js: 串行输入队列；仅同目标、同草稿 ID、同上下文的未发送快照可合并，每次提交独立完成；失败拒绝普通排队项，但保留同草稿已排队的显式删除，附 retry 核验原文，禁止跨目标或上下文恢复。
compose.js: 仅使用原生输入法；首页与全屏共享草稿 ID、整值/选区实时同步、特殊远控暂存、图文一次提交和 IME 恢复；提交等待图片处理及全批重传并冻结附件编辑，按有序 imageIds 绑定草稿；用户显式切换目标或失败后重选当前目标时，保留正文/附件并重建草稿身份、执行队列和输入上下文，激活完成后以当前电脑位置重新同步已有正文；健康状态重复点击不重建，键盘移动选中与前台自动跟随也不触发；保留电脑原文且不反填手机，手机只管理本轮段落；已有手机正文聚焦、页面返回、首次目标就绪或进入全屏即调度全文同步，候选结束补齐镜像，当前编辑面板而非焦点决定正文来源；通用模式持续上传全文，特殊远控暂存才停止预览请求，提交确认结束本轮，失败暂停自动同步但保留显式发送路径，重试沿用草稿 ID/原目标并重新取输入上下文，保留首个真实失败原因；编辑框空白/实时同步/暂存均可见，44–88px 随文字增长，发送与关闭同排；全屏上下文绑定控制会话与电脑输入位置，提交中冻结编辑，关闭取消未发送队列；首页/全屏清空保持草稿 ID 并上传空串，暂停后删除先核验；重建编辑元素并重绑事件，失焦取消 IME 超时探针，镜像始终读取当前首页框。暴露 `pocketdeskComposeSend()`（复用同一业务锁的发送入口，**不是** pad.js 独占的 `pocketdeskSend`）、`pocketdeskHasDraft()`、`pocketdeskCanMotionSend()`（未选目标/发送中/提交锁/组合态/近 700ms 内有输入则 false）、`pocketdeskInputSettled()` 供体感发送门禁查询。
motion-recognizer.js: 翻腕手势纯函数识别器（无浏览器依赖，可 node 单测）；`makeRecognizer(params)` 对“前倾并停住片刻”发候选，对震动/扭转/转屏/数据缺口一律拒绝；阈值全部可配，默认保守，不自动提高灵敏度。
motion-send.js: 翻腕发送的传感器侧；注册 `window.pocketdeskMotion`（权限/起停/预设/状态）与 `window.pocketdeskWristAvailable()`（能力门禁，settings.js 委托它）。采集 DeviceMotion/Orientation 喂给识别器；候选经 `pocketdeskCanMotionSend` 门禁后复用 `pocketdeskComposeSend()` 发送。iOS 经一次用户点按调 `requestPermission`，安卓等安全上下文即视为已授权；默认不自动发送，必须用户开启且已授权。无练习通道：只有活动监听一条路径。
screen-geometry.js: 画面适应、1–6 倍缩放、包含横向旋转的坐标正反投影、位移换算和边界夹取；输入与光标只消费这一份几何，不混用 CSS 像素与桌面点。
screen-gestures.js: 触屏/指针/本地视野手势仲裁，兼容滚轮定位与结束相位；轻点、双击、合并触点采样/显示比例跟手滚动、按时间衰减惯性、捏合、按住放大瞄准及指针长按拖动，取消/第二指加入清理瞄准并松键，不补点击。
screen-pip.js: PiP 整块拖动、八向等比缩放、位置持久化和视口夹取；拖动中只写 transform，结束后保存位置。
screen-frames.js: 单帧请求与持续 JPEG 通道；解码呈现后 ACK，单请求在途、会话代际隔离、超时和降级，只有真实呈现更新画面时钟，停止后禁止交互重新启动采集。
screen.js: 工作台生命周期、小窗屏幕直选、显示器工具栏快捷轮换与菜单选择、默认点击/滚动统一、按需精确瞄准、四入口控制栏、菜单/右键/观看、控制权与画面新鲜度守卫；进入全屏尝试 landscape 方向锁，不支持时旋转画面坐标层；VisualViewport 重排；全屏固定页面并将首页设为 inert，退出恢复滚动位置；返回逐层收起，后台停止画面并释放手势。
style.css: 经典蓝设计令牌与首页基础布局；全局颜色/间距仍从此定义。
app-extras.css: 首页设置、历史、图片和快捷键后置规则，以及米白主题覆盖；加载在基础样式之后。
screen.css: PiP 与正立全屏网格；竖屏底部工具栏，横屏右侧工具栏，输入栏独立占位、输入时隐藏常规工具栏；根页面采用画面底色并隐藏首页，避免 Safari 键盘动画露出底层内容，画面坐标层支持自动横向旋转，内部图片进行缩放平移；瞄准镜与画面共用坐标层，显示真实画面的 3 倍局部。

- 可见输入区始终正立。键盘已打开时点画面仅收起键盘，不能同时点击电脑；toggle 在 pointerdown 捕获状态，避免 blur 抢跑。

输入同步修订（3.0.17）：电脑原文保留且不反填手机，手机只管理本轮段落；删空保持草稿 ID 并立即上传空串，暂停后删除先核验，恢复期间新输入随后补齐。已有手机正文在聚焦、页面返回、首次目标就绪及进入全屏时同步全文。

提交收尾（3.0.18）：app.js 的普通 Return/Enter 快捷键在有手机草稿时委托 send，空框与组合键仍走快捷键接口。compose.js 在确认提交后重建首页/全屏编辑会话，丢弃旧元素迟到的 IME 事件；先结束草稿，再独立保存历史，存储异常不能把已提交误报成失败。

手机设置整合（3.0.23）：触控板内齿轮与 `.pad-tuning` 整体迁入 header 唯一入口 + 底部模态面板，旧 `show-tuning` 状态、`#pad-settings` 节点与 `padCard` 引用一并删除，`exitPadMode()` 不再顺手关面板。三个触控板控件的 ID、范围与 `pd-sens`/`pd-scroll`/`pd-ruler` 全部保留，读写仍在 pad.js。翻腕组以默认关闭的开关占位，未接入传感器前不提供可开启的假开关。

翻腕发送落地（3.0.24）：新增 motion-recognizer.js（纯识别器）与 motion-send.js（传感器侧），经 `scripts/setup-secure-channel.sh` 生成的自签 CA 在 :46487 提供 HTTPS，满足手机运动传感器要求的安全上下文。能力门禁 `pocketdeskWristAvailable()` 现返回真实能力（不支持/非 HTTPS/未授权各有对应原因）；用户开启后复用 compose.js 的 `send()`，受 `pocketdeskCanMotionSend` 门禁约束（设定期/无草稿/输入中/提交中/组合态不误发）。设置面板内提供 iOS 授权按钮、灵敏度预设与「练习（不发消息）」实时倾角条。阈值默认保守、需在真机标定，尚未经过 iPhone/vivo 双机正式验证。

翻腕标定读数（3.0.25）：灵敏度三档带度数直接写进下拉选项（随 `PRESETS` 自动同步），刻度条上画出阈值标记线；练习区改为大字实时倾角 + 「阈值 X° · 本次最大 Y°」读数，并区分「已触发 / 未发送：原因 / 等待抬起（需超过 X°）」。停止练习时给出结论（已达阈值可用 / 差几度或改调灵敏度），传感器不可用时直接说明原因而不是留一个永远不动的读数。灵敏度档位写入 `pd-motion-send` 的 `sens` 字段并在重新加载后灌回识别器；`updateWristUI()` 同时按偏好回填开关状态，避免刷新后开关显示与运行态不一致。settings.js 先于 motion-send.js 解析，故档位恢复放在 `DOMContentLoaded`。

主页输入框唤起键盘（3.0.26）：修掉安卓 Chrome「点输入框不弹键盘」的两个成因。其一，退出触控板模式原本挂在 textarea 的 `pointerdown` 上，会在一次点按尚未结束时就把输入框从 52px 撑回 140px，安卓据此判为无效点按、焦点拿不到；改为只在 `focus` 上退出触控板模式。其二，键盘被系统返回手势收走后 textarea 往往**仍是 activeElement**，焦点无变化时 Chrome 不再弹键盘；在 `pointerdown` 先交还焦点（`visualViewport.height` 比 `innerHeight` 低 120px 以上即视为键盘已展开，此时不动焦点以免打断点选光标），并在卡片上补一次 `click` 聚焦以覆盖点在内边距/空白处的情况。点按按钮、滑杆不抢焦点。

误发与重复输入修复（3.0.27）：`window.pocketdeskSend` 归 pad.js 独占（screen.js 的画面/指针指令通道），compose.js 的发送入口改注册为 `window.pocketdeskComposeSend`，motion-send.js 只认后者。此前 compose.js 在 pad.js 之后加载并覆盖同名全局，使画面里每一次点按、滚动与 `cursor-subscribe`/`take-control` 都转成 `send()`——表现为**没开翻腕也会自动发送**，且随画面可见性与 `auth_ok` 频繁触发。同时安卓专属的输入补丁由 `androidInputPatch`（`/Android/i` UA 判定）收口：残留焦点再聚焦、内边距补聚焦与 IME 卡死自愈三处都会对编辑框 blur→focus，iOS 上听写/输入法会因此把同一段内容再落一遍，表现为**重复输入**。新增 `tests/web-globals.test.cjs` 锁定该全局单一归属、加载顺序与平台门禁。

翻腕练习移除（3.0.28）：练习通道整套删除——页面上的「练习（不发消息）」按钮、大字倾角、阈值刻度条与 `#wrist-status` 一行，以及 `motion-send.js` 的 `startPractice/stopPractice/isPracticing` 与 `onSample` 回调。练习本是为真机标定阈值而设，但灵敏度三档已把度数写进选项（低 30°/中 22°/高 15°），读数面板只是把同一个数重复展示一遍，反而让设置面板越拉越长。翻腕发送只剩「活动监听」一条路径：开开关即监听，可用性原因就地写回 `#wrist-note`（未授权 iOS 仍显示授权按钮）。灵敏度档位与偏好行为不变。
