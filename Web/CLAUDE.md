成员清单

index.html: 面向手机的单页工作台，无模式切换也无模式按钮：应用 Dock + 触控板卡片（收起 96px 精简条）+ 输入区（输入框下方的历史发送面板：清空带二次确认、收起按钮；图片预览）+ 按需打开的画面查看器（**两种形态：默认的 PiP 小浮窗 + 整层全屏（点全屏按钮进入）**；PiP 浮窗无专门拖把、整块任意位置可拖 + 8 个 .screen-resize handle + 只留切屏键与全屏/刷新/关闭三个圆形图标按钮的浮层 + #screen-cursor 鼠标叠加层；**没有状态条**）；触碰触控板自动展开、点输入框自动收起。
console.html: 电脑端控制台（自包含样式与脚本）。五步引导：系统授权（一键跳转设置）、手机扫码连接（局域网 QR + 自动探测的 Tailscale 跨网 QR + 在线状态）、目标应用搜索/增删/排序/自定义图标 + 每个目标的设置展开区（默认打开输入框/触控板偏好、应用专属快捷键组、叠加全局组开关 showGlobal 默认开、内置常用快捷键下拉框 BUILTIN_PRESETS 一键添加刷新/粘贴/复制/撤销/回车/锁屏/关闭等）、快捷键管理（录制产出语义串 hotkey 如 "Cmd+Shift+Z"/"Return"：主键只认 event.code 物理键位、不回退 IME 可污染的 event.key，拦截 isComposing 与纯修饰键；录制器为作用域模型 recordCtx，全局与应用专属共用同一 keydown 监听，录完即存，反馈就地显示在触发按钮上；键位标签用 .keycap 样式、label 与键位展示重复时只显示一个；支持重录/排序/删除）、最近动作（每 3 秒轮询 /api/status 的 log 字段，时间/结论徽章/动作+前台/说明四列网格，结论分三色：绿=已生效、琥珀=已发出未确认、红=未执行或失败——手机端点了没反应时来这里查第一现场）；默认经典蓝主题，:root[data-theme="muji"] 按需切换米白克制风；头部"经典蓝/米白"分段开关 POST /api/theme 写 Mac 本机，手机页自动跟随。
screen.js: 复用 app.js 的 authHeaders；**入口是发送行的电脑按钮，点开即 PiP 浮窗，浮层有全屏按钮可切整层全屏（非模态 dialog，开着时主页触控板仍可操作）**；转屏交给手机自己转，画面比例由 object-fit 兜底；`?v=` 之外的版本说明见 style.css 条目。**panel.open 是唯一真值源**，不另设 viewState 上刷；**失败分支先分清"锁屏"还是"屏幕睡了"**：调 `GET /api/screen/state` 问 `locked`——真锁屏就显示"电脑已锁屏，请在电脑上输入密码解锁"（macOS 安全策略，ScreenCaptureKit 拿不到锁屏画面，无解，别再重试空转）；没锁屏却取不到画面则 `POST /api/screen/wake` 唤醒显示器并自动重试一轮（`wakeRetried` click 参数（点一下 = 移过去 + 左键单击，一条消息原子执行）与 **clickState**（1=单击，2=双击的第二下；**第一下立刻发出、不等双击窗口**，否则每次单击都凭空多 350ms 延迟）——双击判定为 350ms + 28px 容差 + 同显示器（`lastScreenTap`，三连点得到 1/2/1 而非 2/2/2，stop() 立刻补一帧（不能拿点击前开始抓的旧帧冒充结果）；拖完/平移完对随后那次 click 的屏蔽已改为**消费一次**（`dragClickPending`）——以前是"400ms 内一律忽略"，拖完窗口想立刻点画面会被吞掉；**全屏里点画面（点输入框）会经 `window.pocketdeskAfterTap` 问 Mac 焦点（`/api/focus-probe`，仅 editable/unknown 弹、notEditable 不弹），直接唤起手机原生键盘**——**没有可见面板、也没有发送按钮**：竖屏全屏整层转 90° 后 HUD 的最小化/刷新/关闭落在手机右侧，贴底面板必然压住它们（那是退出全屏的唯一出路），发送交给原生键盘自带键（`enterkeyhint=send`）；代理 `#kb-proxy` 是 1px 隐形 textarea，**挂在 `#screen-view` 内部**（挂 `<body>` 的话进入原生全屏后整份文档只剩 panel，代理失焦、键盘弹不出来）并钉在左上角（贴底会被浏览器的 scroll-into-view 把整页顶上去）；键盘抬起期间 `window.pocketdeskKeyboardActive()` 为真，本文件的 resize 重排（含 updateRotation）一律跳过——键盘引起的视口变化不是转屏，重排只会让画面缩一下又弹回来，落下后由 `window.pocketdeskKeyboardClosed` 补一次真实重排；关闭查看器 / 退出全屏经 `window.pocketdeskHideKeyboard` 一并收掉；**全屏态画面缩放由 screen.js 自己实现双指捏合**（1x–6x + 单指/双指拖动平移，不另设放大按钮）——`.screen-view` 上的 `touch-action: none` 已把浏览器原生捏合关掉，指望它等于没有，只能自己接 Pointer Events；几何因此分两层：`baseContentRect()` 未变换（点击映射用）→ `contentRect()` 叠 zoom（光标叠加用），退出全屏/关闭/换屏/转屏都重置或 clamp；**全屏自动横铺（不锁方向）**：竖屏全屏时直接给 panel 加 `.rotated` 类做 CSS 90° 旋转，把 16:9 画面横铺满屏——**不依赖 screen.orientation.lock（iOS Safari 根本没有该 API、网页锁不了方向）**，iPhone/安卓都生效；`updateRotation()` 在进/出全屏与 orientationchange/resize 时判定（仅全屏且 innerWidth<innerHeight 才转），`enterFullscreenLayout()` 顺带 requestFullscreen 藏浏览器栏、`exitFullscreenLayout()` 退出时一并撤掉；不再有"请把手机横过来"提示；**授权联动**：撞到录屏权限墙时自动 POST /api/screen/permission 把电脑端系统弹窗喊出来（每次打开查看器限一次），随后每 3 秒轮询 /api/screen/displays 等用户在电脑上点「允许」，生效即自动接上画面，约 90 秒无果再退到手动指引；服务端 canRequest=false（本机已弹过窗，系统不再弹）时不空等，直接引到系统设置。**鼠标叠加层已停用，改看画面里烘焙的鼠标（cursor=1）**：30Hz 坐标在 280px 小窗上既看不清也无必要，而它每 33ms 推一次、每帧重画一次，paintCursor 还要读 image.offsetWidth（强制重排），与浮窗拖动抢主线程——这是"拖动很慢"的帮凶。恢复办法写在 syncCursorSubscription 的注释里（wanted 改回原条件即可，几何仍共用 baseContentRect()）。**拖动路径上禁止读布局**：moveDrag → paintPanel 每帧只写 style，绝不读 offsetWidth/getBoundingClientRect——写完立刻读就是强制同步重排（layout thrashing），60Hz 下足以让拖动明显掉帧；故 paintPanel 里的 revealHud() 与 paintCursor() 都带 `if (!dragState)` 守卫（前者还避免拖动全程反复重置 2.6s 定时器）。**整块拖动改用 transform: translate3d() 实时位移（松手才烤回 left/top），纯合成不触发大图重绘，手机才跟手；`.screen-view.pip` 持 `will-change: transform` 预提升合成层，resize 因改尺寸仍走 left/top 重绘（可接受，且 resize 频率远低于拖动）。**自动更新只有 scheduleNext() 一个调度入口**，回调里必须把 timer 置空——否则 clearTimeout 后句柄仍在、下一轮 `!timer` 恒假，更新跑完第二帧就悄悄停住且不报任何错；同理，先置 `updating=false` 再 scheduleNext 是句空话（scheduleNext 内部直接 return），要重试就别停表。
style.css: 手机页唯一样式来源（控制台样式内联在各自 HTML，令牌取值与本文件保持一致）。:root 里的设计令牌（颜色/间距/圆角/字号/动效）之外不允许出现硬编码色值。经典蓝玻璃主题为默认，:root[data-theme="muji"] 覆盖为米白克制风（米白 #f5f3ee 底 + 深炭字 + 赭红 #b74127 单一点缀、去发光去渐变去毛玻璃、方正小圆角）。两个主题共用同一套令牌名与选择器，切换零结构改动。主题是服务端状态，默认 classic（经典蓝）：电脑控制台头部"经典蓝/米白"分段开关 POST /api/theme 写 Mac 本机，手机页无按钮、经 /api/status 轮询跟随（≤5s），localStorage 只存上次已知值缓解刷新闪烁。**横屏**：`orientation: landscape` 且 `max-height: 560px` 时浮层再压薄一档（竖屏全屏由 `.screen-view.fullscreen.rotated` 整层 CSS 旋转 90° 横铺满（.screen-view.fullscreen：隐藏 resize、HUD 常显、不画鼠标叠加、画面可双指缩放）；`#screen-image` 的 `transform-origin: 0 0` 是硬约束，screen.js 的 tx/ty 全按它推导，改 CSS 必须同步改 JS；全屏态 `.screen-viewport` 关掉 overflow 交给 JS 平移，绝不出现两套滚动系；全屏竖屏改走 `.rotated` CSS 旋转横铺（不依赖 screen.orientation.lock，iOS Safari 无此 API）；`#screen-rotate-hint` 提示已删除，旋转兜底不再需要）。**PiP 浮窗** 走 `.screen-view.pip` 选择器：`position: fixed` + JS 写到 inline style 的 left/top/width/height，阴影 + 圆角，::backdrop 透明（让主页透出来）；**8 个 resize handle** 是浮窗边缘 18px 宽的带（nw/n/ne/e/se/s/sw/w），CSS 给出位置与 cursor（nwse-resize/nesw-resize/ns-resize/ew-resize）。**层叠顺序是硬约束，改前先想清楚**：`.screen-viewport`(1) < `.screen-resize`(3) < `.screen-hud`(5, 子元素再 relative z-index:1)，HUD 必须压过 handle，否则"刷新/关闭"点了变成拖窗口；pip 态 HUD 顶部让开 20px 才不与 18px 的 resize 带抢地。**`.screen-view` 基类绝不能写 `margin: auto`**——fixed 定位下 left/right/width 同时非 auto 时 margin:auto 会去平分剩余空间，算出负 margin 把整层推偏（"画面只剩一半"的历史根因，全屏态虽已删除，这条约束仍然有效）；`.hud-icon` 是 34px 圆形图标按钮 + 半透明底（**半透明底是硬要求**：白色图标遇到亮色画面会直接消失）；刷新按钮不再写"获取中"文字、只留图标。`.screen-cursor` 叠加层用 transform 定位（合成层不触发重排）、`pointer-events: none`（吃掉点击就会废掉"点画面移光标"）、热点对齐 SVG 箭头尖端（路径起点 1,1，svg 偏移 -1px）。
app.js: 手机页交互与本地 API 客户端。点击唤醒、发送命令（文字 + 可选图片：选图压缩到 2048px JPEG 预览，图片经 /api/image 预上传，发送时 SendCommand 携带文本与 usePendingImage 标记；服务端先输入文字，再经 Mac 剪贴板 Cmd+V 粘贴图片并统一提交）；手动激活目标后按其 openPanel X"一律显示识别到的真实应用名；触控板 Pointer Events 手势状态机（单指移动/点按/长按拖动、双指滚动/右键），增量经 rAF 合并后发往 ws:46388；**点击一律用 clickState 而非 count**：发 `{t:'click',clickState:1|2}` 表示"这一下是序列中的第几下"（各只一组 down/up）；旧字段 `count` 是"完整点击次数"、服务端会按 1...count 循环执行，所以先 count=1 再 count=2 会被执行成 **3 次点击**——服务端仅为旧客户端保留 count，新前端禁止再用；历史面板展开时按钮高亮、相同内容去重、清空需二次确认（3.5s 自动还原）；快捷键按钮条随选中目标切换：有专属组时前排专属 + 后排全局（showGlobal=false 只显专属，默认叠加），无专属组用全局组（过滤默认 undo/copy/paste 示例），心跳边沿比对 targets 与 shortcuts 5 秒内跟随服务端，Enter/Return 等别名归一显示同一符号、名称与键位重复时只显示一个，点击 POST /api/shortcut-trigger 注入 Mac 前台；配对 token 管理（URL ?token= → localStorage → 写请求 Authorization 头与 WS 首帧 auth）、主题跟随（applyTheme 在 boot 与心跳里应用 /api/status 下发的 theme）。**同一条 ws:46388 也收下行**（此前是纯上行）：ws.onmessage 分发 auth_ok / cursor / error / closed，经 `window.pocketdeskOnWSMessage` 供 screen.js 订阅；`wsReady` 只说明 socket 打开、**不等于鉴权通过**，要等服务端 auth_ok 才是 `wsAuthorized`（回环豁免也回执，所以前端只有一条判定路径）。**全屏原生键盘模块（#kb-proxy）**：showKeyboard/hideKeyboard 两个钩子挂到 window 供 screen.js 1px 的隐形输入代理（保留真实尺寸以便可聚焦、唤起原生键盘，但文字/光标/边框/背景全透明且 opacity:0 而非 display:none——后者浏览器根本不弹键盘；font-size 必须 ≥16px，否则 iOS 聚焦时自动放大整页；pointer-events:none 绝不吃画面上的点击），敲的字经 wireComposeIME(kbProxy, textEl, recreateKbProxy) 镜像回主页 #text（textEl 仍是直播同频的唯一真值源）实时注入 Mac 当前聚焦输入框——全屏时手机看到的就是电脑画面，文字出现在该出现的地方，不再抄一遍；**Gboard「上滑清空」自愈**：该手势把当前元素的原生 IME 会话彻底搞死（敲字不出 input、点不进、只能刷新整页），唯一可靠解法是丢掉被污染的元素、整个换一个全新 textarea（recreateKbProxy，新元素带全新原生编辑会话）——所以代理一律 buildKbProxy() 现造现用，绝不依赖 blur→focus 同元素（对 Gboard 无效）；命中条件为 wireComposeIME 检测到「一次 input 从非空一步归零」或「beforeinput 后 700ms 没回 input」，或 showKeyboard 时「代理仍聚焦却本轮没收到过字」，任一命中即换元素；重建期间用 kbRecreating 抑制旧元素移除触发的假 blur 误触发重排；主页 #text 仍走轻量的 recoverIME（blur→focus）。**发送只走原生键盘右下角“发送”键（enterkeyhint=send）**，等价于回车，sendFromKeyboard 复用主页 send()（已同频时只是补一次回车，发完草稿清空则自动收起键盘），网页不再自造发送按钮；**键盘抬起期间页面不许被顶起**：代理钉在左上角 + kbActive 期间 pinScroll() 把 window/scrollingElement 的滚动摁回 0（focus 后 0/60/150/300ms 各摁一次，键盘动画期间浏览器会连滚好几帧）；**收起判定只看失焦**（blur → 复位并通知重排），不再用 visualViewport 内缩量——没有可见面板也就不必猜键盘高度，且 hideKeyboard 刻意不清代理 value（下次唤起重播种；清了可能被 recoverIME 的 blur→focus 把真值覆盖成空）；IME 防御已抽成元素参数化函数 wireComposeIME(el, mirrorTo)，主页与键盘代理共用。麦克风/语音输入已移除（局域网 HTTP 非安全上下文，webkitSpeechRecognition 本就不可用，Gboard 自带麦克风够用）。

## 全屏优化 v2.9.19（FULLSCREEN_POINTER_PROPOSAL.md 落地，除 P2/WebRTC 外基本完成）
- **统一几何 + 手势状态机（§4/§5）**：`baseContentRect()` 加缓存（输入不变不重算，连续光标帧只读缓存，不再每帧读 offsetWidth 强制重排）；全屏改 `onFsPointerDown/Move/Up` 状态机（idle→move/drag/view/scroll），用 setPointerCapture 收尾，全屏 pointerdown 即 preventDefault 取消兼容 click（PiP 仍走 img.click→sendTap）。
- **单指语义变革（§3，与旧版相反）**：全屏单指=远端控制电脑——轻点=立即单击（第一下不等待双击窗口）、快速两下=双击(clickState 2)、小移=绝对跟随移动鼠标(`tap` click:false)、按住过 400ms=远端拖动(`down`+`drag` 相对像素位移+`up`)；双指=只缩放/平移手机画面(view transform)。`clientToRatio()` 统一做逆旋转+object-fit 留白剔除，单击/移动/拖动/右键/滚动共用。远端拖动像素位移 = 比例差 × 显示器逻辑分辨率（displays 接口现带 width/height，存 displaySize Map）。
- **全屏权威光标（§6 层2）**：`syncCursorSubscription` wanted 改为仅全屏态订阅 30Hz 光标且关烘焙(cursor=0)；`paintCursor` 去掉 !isFullscreen 守卫、改用 cursorLinkLive() 判定；链路断/非全屏回退 cursor=1 烘焙鼠标。几何已缓存，叠加层开销可控。
- **本地触点环（§6 层1）**：`#screen-touch` 在 viewport 内随 .rotated 一起转，手指接触下一帧显示、140ms 后淡出，只代表收到触摸。
- **右键 / 滚动工具（§3）**：全屏 HUD 加 `#screen-rightclick`(作用于最近远端光标位置 lastRx/lastRy)、`#screen-scroll`(切换滚动模式，开启后单指拖=滚动 `scroll`+`scrollEnd`，不抢"单指控电脑"那根手指)；均 .fs-only 仅全屏显示。
- **动态帧率（P1）**：`scheduleNext` 支持动态间隔，交互(点/移/滚/拖/缩放)经 `boostFps()` 把取帧频率从 1fps 短时提到 ~4-5fps，空闲降回；仍守"同时仅一个截图在途"。
- 版本 bump→2.9.19，仍**未 git 提交**；P2(WebRTC 视频)未做（独立大项目）。

## 全屏后续微调 v2.9.20–2.9.22
- **v2.9.20 键盘按钮归位**：`#kb-toggle` 从独立浮层移入顶部 HUD 栏（与全屏/刷新/关闭一组），class `hud-icon kb-toggle fs-only`，仅全屏显示；再点一下收起（toggle 早已实现）。竖屏 `.rotated` 整层转 90° 后随其余 HUD 落到手机右侧，无需单独逆旋。
- **v2.9.21 放大/缩小回归修复**：v2.9.19 全屏状态机 `onFsPointerDown` 只把**第二根**手指登记进 `zoomPointers`，第一根漏登 → `zoomPointers.size>=1` 永远不成立 → 双指捏合分支进不去，pinch/pan 整段失效。修复：第一根手指也 `zoomPointers.set(...)`；`onFsPointerUp` 非 view 分支补 `zoomPointers.delete` 清残留，免误判成第二指。本版还顺手把 style.css(2.9.18)/screen.js(2.9.19) 版本号统一到 2.9.21。
- **v2.9.21 曾移除右键/滚动两个按钮**：用户反馈"看不懂、点击没反应"——两者是 v2.9.19 自作主张加的、用户没要求；右键无可视反馈、滚动只靠图标高亮用户没察觉。故先移除，待用户拍板。
- **v2.9.22 恢复右键/滚动按钮 + 加上手机端反馈**：用户确认"这两个按键需要，但都没生效"。恢复 `#screen-rightclick`/`#screen-scroll`（均 `fs-only` 仅全屏显），并新增 `showToast()`——右键→"已发送右键"、滚动开关→"滚动模式：开/关（单指拖=滚动）"，fixed 定位不受 `.rotated` 旋转影响、始终正立居中底部。右键作用点仍是 `lastRx/lastRy`（最近一次远端光标，需先用单指把光标移到目标再点右键）；滚动开启后单指拖=滚动、不与"单指控电脑鼠标"抢同一根手指。**全屏单指语义保留 v2.9.19「一指控 Mac 鼠标」**（用户拍板，不退回旧版「一指平移画面+双指捏合」）。版本 bump→2.9.22。

## 全屏键盘修复 v2.9.23
- **图标 toggle 收不起（高亮消不掉）**：根因是 **blur 抢跑**——点 `#kb-toggle` 会让 `#kb-proxy` 失焦，blur 监听先把 `kbActive` 翻成 false，click 处理 `if (kbActive) hideKeyboard() else showKeyboard()` 读到的已是 false，于是第二次点击反而 `showKeyboard()` 重新弹起。修复：在按钮 `pointerdown` 时先快照 `kbToggleWasActive = kbActive`（blur 发生前），click 改判快照值决定开/关。**凡是"点按钮 toggle 某个聚焦元素状态"的场景都要防这个坑：判据必须在 blur 发生前捕获。**
- **点画面顶出/卡住键盘**：`onFsPointerDown` 开头加键盘守卫——全屏里若 `pocketdeskKeyboardActive()` 为真，点画面直接 `pocketdeskHideKeyboard()` 收起并返回（这一下不顺便点 Mac，避免误触）；键盘关掉后再点画面才控制 Mac。点画面从此绝不会开/顶出键盘。
- 版本 bump→2.9.23。
